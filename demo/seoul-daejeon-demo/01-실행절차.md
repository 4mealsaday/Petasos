# 천안→KAIST 데모: 실행 절차

최종 갱신 2026-11-12. macOS(Apple Silicon)에서 **실제로 돌려서 확인한** 순서다.
README와 다르거나 README에 없는 부분은 **⚠️**로 표시했다.

**매번 하는 건 3장부터**다. 1~2장은 환경이 깨졌을 때만.

## 1. 최초 1회만

### AVD

```sh
# ⚠️ 반드시 Pleos 전용 디바이스 프로파일을 쓴다.
# 일반 automotive_1024p_landscape로 만들면 1024x768로 잡혀 UI가 깨진다.
avdmanager create avd -n "Pleos_Connect_v2.1.0" \
  -k "system-images;android-34;pleos_car_emulator;arm64-v8a" \
  -d "Pleos_Connect_v2_0"
```

생성 후 `~/.android/avd/Pleos_Connect_v2.1.0.avd/config.ini`를 고친다
(avdmanager가 디바이스 정의의 기본 방향·RAM을 따라가지 않는다):

```ini
hw.initialOrientation=landscape
hw.ramSize=4096
hw.gpu.enabled=yes
disk.dataPartition.size=6442450944
```

기대값: **2560x1440, density 160, landscape**.


## 2. 인증서 + 빌드 (인증서 만료 시 / 코드 바뀌었을 때)

```sh
PYTHONPATH=server .local/server-venv/bin/python server/dev-local-https.py prepare
```

- ⚠️ **`prepare` 직후 `git restore`로 CA 파일을 되돌리면 안 된다.** 되돌리면 서버가
  `DEBUG_CA_OUT_OF_SYNC`로 기동을 거부하고, 앱도 TLS 핸드셰이크에 실패한다.
- ⚠️ **`prepare` 후에는 반드시 APK를 다시 빌드**해야 한다. 디버그 앱은 CA를 adb push가 아니라
  **APK에 구워진 리소스**로 신뢰한다 (`debug_network_security_config.xml`).
- 인증서 7일 / CA 30일 만료.

```sh
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew assembleDebug        # .env의 네이버 지도 키도 이때 APK에 들어간다
```

> 테스트까지 돌리려면 `./gradlew :app:testDebugUnitTest`. **1건은 기존 실패**다
> (`StrictJsonDecimalTest`, JBR 21 환경 추정). 테스트 실패 시 `assembleDebug`가 함께 중단되므로
> 빌드만 필요하면 `assembleDebug`만 따로 실행한다.

## 3. 에뮬레이터 부팅

```sh
export PATH="$HOME/Library/Android/sdk/platform-tools:$PATH"
~/Library/Android/sdk/emulator/emulator -avd Pleos_Connect_v2.1.0 \
  -no-snapshot-load -no-boot-anim -dns-server 8.8.8.8,1.1.1.1 &
adb wait-for-device
until [ "$(adb shell getprop sys.boot_completed | tr -d '\r')" = 1 ]; do sleep 2; done

# ⚠️ Car 서비스가 올라올 때까지 기다린다 (보통 10초 이내)
until adb shell dumpsys car_service --help >/dev/null 2>&1; do sleep 5; done
```

> ⚠️ **에뮬레이터를 오래(수 시간) 켜두면 Car 서비스가 죽는다.**
> `adb logcat | grep "car_service not ready"`에 로그가 쌓이고, 앱에는
> **"차량 연결 상태를 확인하고 있어요"만 뜨고 "동행 시작" 버튼이 사라진다.**
> `VehicleUxPolicy.available`이 false가 되어 컨트롤이 숨겨지기 때문이다.
> **해결은 에뮬레이터 재부팅뿐.** 데모 전에는 새로 부팅하고 시작하는 걸 권한다.

## 5. 설치 · 권한 · 토큰

```sh
cd ~/Desktop/Develop/Petasos
adb install --user 10 app/build/outputs/apk/debug/app-debug.apk

adb shell appops set --user 10 com.petasos.app SYSTEM_ALERT_WINDOW allow
adb shell pm grant --user 10 com.petasos.app android.permission.SYSTEM_ALERT_WINDOW

adb emu avd hostmicon                       # 호스트 마이크
adb emu geo fix 127.1489 36.8099            # 출발: 천안역
adb reverse tcp:8443 tcp:8443
```

> ⚠️ **위치·마이크 권한을 `pm grant`로 미리 주지 말 것.**
> 온보딩이 건너뛰어져 홈 화면 컨트롤("동행 시작")이 **렌더되지 않는다.**
> 앱 안에서 정상 흐름으로 허용해야 한다. (`SYSTEM_ALERT_WINDOW`는 예외 — 미리 줘야 한다)

### 서버 토큰 — ⚠️ run-as 방식

README의 `/data/local/tmp/petasos-demo` 방식은 **이 자동차용 이미지에서 SELinux가 막는다**
(`avc: denied { write } ... tcontext=shell_data_file`).

```sh
# cache 디렉터리는 앱이 한 번 떠야 생긴다
adb shell am start --user 10 -n com.petasos.app/.MainActivity
sleep 5

adb push .local/server/device-provisioning.token /data/local/tmp/demo-server.token
adb shell run-as com.petasos.app --user 10 \
  cp /data/local/tmp/demo-server.token \
     /data/user/10/com.petasos.app/cache/demo-server.token
adb shell rm /data/local/tmp/demo-server.token

adb shell am broadcast --user 10 -f 0x20 -p com.petasos.app \
  -a com.petasos.app.debug.PROVISION_SERVER
```

- ⚠️ 경로는 `/data/data/`가 아니라 **`/data/user/10/`** (보조 사용자라서)
- 확인: `adb logcat -d | grep DemoResetReceiver` → `Demo server configuration saved`

### 영상 모드

```sh
adb shell am broadcast --user 10 -f 0x20 -p com.petasos.app \
  -a com.petasos.app.debug.SET_VIDEO_MODE --ez enabled true
```

지역당 대표 이야기 1편만 재생된다. 끄려면 `--ez enabled false`.

## 6. 앱에서 시작하기

화면을 보며 **직접** 진행한다. 순서를 건너뛰면 안 된다.

1. **계속하기**
2. **관심사 선택** (역사·음식 추천) → **시작하기**
3. **동행 시작**
4. 권한 대화상자를 모두 **허용** — 오디오 녹음 → Pleos 권한("알 수 없는 작업") → 위치
5. 내비가 앞으로 나오고 오른쪽에 **파란 말하기 버튼**, 아래에 **자막 카드**가 뜨면 준비 완료
6. 내비에 "경로 탐색 오류"나 "경로 안내 재시작"이 뜨면 **닫기** (앱 동작과 무관)

> ⚠️ **"안내 종료"를 누르지 말 것.** 이야기 재생 자체는 GPS 기반이라 계속되지만,
> 내비 배경(경로선·턴바이턴)이 사라져 녹화본을 다시 찍어야 한다.

> ⚠️ **주행이 끝나면 반드시 "동행 끝내기"를 누른다.** 음악이 흐르는 중에 그냥 두면
> 끊긴 음악 체크포인트가 남고, 다음 주행에서 **첫 이야기가 영영 시작되지 않는다**
> (`PlaybackLookahead`는 `musicCheckpoint == null`일 때만 첫 이야기를 띄운다).
> `scripts/demo-reset.sh`가 이걸 자동으로 처리하므로, 리셋 스크립트를 쓰면 신경 쓰지 않아도 된다.

## 9. 콘텐츠를 바꿀 때

새 이야기를 넣는 전체 경로. **`approve`는 기존 이야기 교체만 하므로 새 지역은 `add`를 쓴다.**

```sh
# 1) 평가 세트 — ⚠️ --region 없이 돌리면 기존 고정 파일 5개를 덮어쓴다
PYTHONPATH=server .local/server-venv/bin/python server/tools/story_lab.py build-eval \
  --pack cheonan-kaist --region 43113 --places 8

# 2) 생성 (--all-facts: 출처를 섞어 쓰게 함)
PYTHONPATH=server .local/server-venv/bin/python server/tools/story_lab.py generate \
  --prompt-version story-guide-v3 --region 43113 --count 4

# 3) 사람이 읽고 고른 뒤, 번들에 추가
PYTHONPATH=server .local/server-venv/bin/python server/tools/story_lab.py add \
  --region 43113 --region-name "흥덕구" --from story-guide-v3 --index 3 \
  --like 44131 --tags history \
  --base demo/stories/cheonan-kaist-v1.json --out demo/stories/cheonan-kaist-v2.json \
  --review-basis "..."

# 4) 팩 재생성 + 앱 설치
PYTHONPATH=server .local/server-venv/bin/python server/tools/build_pack.py \
  --scenario cheonan-kaist --version 3 \
  --stories demo/stories/cheonan-kaist-v2.json --install
```

**그다음 반드시 앱 코드 두 곳을 고친다:**

1. `BundledStoryCatalog.SHA256` ← build_pack이 출력한 해시
2. `DemoVideoMode.REPRESENTATIVE_STORY_IDS` ← `add`가 출력한 UUID (안 넣으면 영상 모드에서 재생 안 됨)

그리고 **리빌드 → 재설치**.

### ⚠️ 콘텐츠를 바꿨으면 `pm clear` 가 필수다

`adb install`은 앱 데이터를 보존하고, 콘텐츠 설치기는 **이미 설치된 팩을 덮어쓰지 않는다.**
그래서 새 이야기가 **DB에 영영 들어가지 않고**, 앱의 허용 목록(새 UUID)과 DB 내용(옛 UUID)이
어긋나 **해당 지역 이야기가 통째로 건너뛰어진다.** 로그에는 아무 오류도 남지 않는다.

```sh
adb shell pm clear --user 10 com.petasos.app
```

그다음 **권한 → 온보딩 → 토큰**을 다시 해야 한다(5·6장). `pm clear`는 권한·관심사·서버 토큰도 지운다.

DB에 실제로 들어갔는지 확인하는 법:

```sh
adb shell run-as com.petasos.app --user 10 \
  cat /data/user/10/com.petasos.app/databases/petasos.db > /tmp/petasos.db
python3 -c "
import sqlite3
c = sqlite3.connect('/tmp/petasos.db')
for r in c.execute('''select b.region_code, s.title, s.story_id from story_region_binding b
                      join story s on s.story_id=b.story_id order by b.region_code'''):
    print(r)"
```

같은 쿼리로 **주행 후 실제 재생된 이야기**도 확인할 수 있다(`playback_attempt`의 `state='completed'` 조인).
로그의 `mode -> STORY`는 지역 귀속이 애매해서, **판정은 DB로 하는 쪽이 정확하다.**

## 막혔을 때

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| "차량 연결 상태를 확인하고 있어요"만 뜨고 버튼 없음 | **Car 서비스 사망** | 에뮬레이터 재부팅 |
| 온보딩 없이 바로 재생 화면, 컨트롤 없음 | 권한을 미리 부여함 | `pm clear` 후 앱에서 정상 흐름으로 |
| UI 비율이 깨짐 | AVD가 일반 automotive 프로파일 | 1장으로 AVD 재생성 |
| 서버가 `BLOCKED`로 기동 실패 | `DEBUG_CA_OUT_OF_SYNC` | `prepare` 재실행, `git restore` 금지 |
| 앱이 서버 연결 실패 | APK의 CA가 서버 인증서와 불일치 | `prepare` → **리빌드** → 재설치 |
| 이야기가 아예 안 나옴 | 팩 해시 불일치 (**조용히 실패**) | `shasum -a 256`로 `BundledStoryCatalog.SHA256`과 대조 |
| **특정 지역에서만 안 나옴** | **DB에 옛 이야기가 남아 있음** | `pm clear` 후 재설정 (9장). DB 조회로 확인 |
| 특정 지역에서만 안 나옴 | 영상 모드 UUID 누락 | `REPRESENTATIVE_STORY_IDS` 확인 |
| 첫 이야기가 영영 안 시작됨 (`mode=IDLE`, `target=null`) | 끊긴 **음악 체크포인트** | 동행을 정상 종료해야 한다. `demo-reset.sh`가 자동으로 처리 |
| 이야기가 음악에 밀려 안 들어감 | 구간 체류가 짧음 | `scenario.json`의 `videoStorySeconds` (기본 45, 이 데모는 70) |
| 랜드마크가 `DROPPED` | 체류를 너무 늘려 **지나친 뒤 호출됨** | `videoStorySeconds`를 과하게 키우지 말 것 (120초에서 발생) |
| 청주를 순식간에 통과 | `storyGroups` 누락 | `scenario.json` 확인 |
| `cp: Permission denied` | 경로가 `/data/data/` | `/data/user/10/`로 |
| 빌드가 TransformException | **디스크 부족** | 용량 확보 (에러 메시지가 원인을 가림) |
| 답변이 "연결할 수 없어요" | 서버 미기동 / `adb reverse` 끊김 / 토큰 만료(24h) | 4·5장 재실행 |
| 답변이 "모르겠어요" | 그 내용을 **아직 안 들었음** | 해당 이야기가 끝난 뒤에 질문할 것 |
