# 천안 → KAIST 데모: 구현 현황

최종 갱신 2026-11-12. 이 문서는 **데모 시나리오를 다듬기 위한 기준표**다.
"무엇이 실제로 동작하고, 무엇이 미리 구워진 것이고, 무엇이 아예 불가능한지"를 코드 기준으로 정리했다.
시나리오를 고칠 때마다 이 문서의 표를 같이 고친다.

> 폴더 이름 `seoul-daejeon-demo`는 처음 만들 때의 잔재다. 내용은 **천안→KAIST** 데모 기준이다.
> 기존 서울→대전 데모(`demo/scenarios/seoul-daejeon/`, 팩 `seoul-daejeon`)는 **그대로 남아 있고 건드리지 않았다.**

## 0. 한눈에 보는 상태

2026-11-12 자동 반복 주행으로 검증. **판정은 기기 DB의 `playback_attempt`(실제 완료 기록) 기준**이다.

| 장면 | 상태 | 확인 방법 |
| --- | --- | --- |
| 천안 동남구 — 천안삼거리 이야기 | ✅ | DB: 문단 2/2 완료 |
| 청주 흥덕구 — **신규** 「운천동 흥덕사 터」 | ✅ | DB: 문단 2/2 완료 |
| 청주 서원구 — 음악 구간 | ✅ | MUSIC 모드 유지 |
| 대전 대덕구 — **신규** 「신탄진 길목의 식당들」 | ✅ | DB: 문단 2/2 완료 |
| 대전 유성구 — 과학공원 이야기 | ✅ | DB: 문단 2/2 완료 |
| 🗼 한빛탑 창밖 안내 끼어들기 | ✅ | `window speak RIGHT_FRONT mode=STORY` → `SPOKEN` |
| 말하기 → 질문 → AI 답변 | ⏳ | **실제 마이크 발화 필요. 사람이 1회 확인해야 함** |
| 음악 무드 선택("신나는 걸로") | ⏸ | 합의대로 맨 마지막 작업 |
| 이야기 사이 음악 1곡으로 제한 | ❌ | **시도했다가 되돌림** — 아래 참고 |

전체 주행 약 **5~6분** (`videoStorySeconds: 70` 기준).

### 손대면 안 되는 것: 음악 제안

이야기 사이 곡 수를 줄이려고 두 가지를 시도했다가 **둘 다 이야기 재생을 망가뜨려 되돌렸다.**

| 시도 | 결과 |
| --- | --- |
| 한 곡 뒤 제안 중단 | 플래너가 다음 이야기 시점을 `offeredDurationMs`로 계산해서, 제안이 끊기면 **이야기 예약이 멈춤** |
| 같은 곡 반복 제안 | 역시 경계 계산이 어긋나 흥덕구 이야기가 밀림 |
| `DEMO_MUSIC_DURATION_MS` 15→45초 | 음악이 구간을 차지해 **다음 이야기가 창에 못 들어감** |

`AutomaticMusicPlaybackBridge`와 `DEMO_MUSIC_DURATION_MS`는 **원본 그대로 두는 게 맞다.**
곡 수를 줄이려면 이야기를 길게 하거나 구간을 짧게 하는 쪽으로 접근할 것.

## 1. 누가 무엇을 하는가

가장 자주 헷갈리는 지점부터. **OpenRouter는 글자만 만들고, 소리는 전부 Pleos가 낸다.**

| 역할 | 담당 | 위치 |
| --- | --- | --- |
| 목소리 출력(TTS) | **Pleos SDK, 온디바이스** | `platform/pleos/speech/PleosSpeechOutput.kt` (`ai.pleos.playground.tts.TextToSpeech`) |
| 음성 인식(STT) | **Pleos SDK, 온디바이스** | `platform/pleos/speech/PleosPcmSpeechInput.kt` (호스트 마이크 PCM 입력) |
| 답변 텍스트 | **OpenRouter(Claude)** | Mac 로컬 HTTPS 서버 `server/`가 중계 |
| 내비 제어 | **Pleos NaviHelper** | `platform/pleos/navigation/` |
| 지도 바탕("내 여행") | **네이버 Maps SDK** | `.env`의 `PETASOS_NAVER_MAPS_CLIENT_ID` |

Pleos의 음성 어시스턴트(Gleo)는 **쓰지 않는다.** TTS/STT SDK를 직접 호출한다.
Gleo는 TTS 엔진이 아니라 **음성 명령 라우터**이고(사용자 발화 → 앱 함수 호출), Action 타임아웃이 **7초**라
이야기 낭독에 쓸 수 없다. LLM SDK도 에뮬레이터 2.1.0에서 **제공 종료**됐다.

## 2. 기능별 실시간 여부

데모에서 "AI가 지금 만들어내는 것"과 "미리 만들어 둔 것"의 경계.

| 기능 | 담당 | 실시간? |
| --- | --- | --- |
| 이야기 12편 본문 | APK에 구워진 콘텐츠 팩 (`assets/content/packs/cheonan-kaist.json`, SHA-256 고정) | ❌ 사전 생성 |
| 창밖 랜드마크 안내 1곳 | 같은 팩 | ❌ 사전 생성 |
| 다음 이야기 추가 생성 | `AutomaticStoryGeneration` → 서버 `task:"story"` | ✅ 기존 이야기를 seed로 |
| **질문 답변** | 서버 `task:"answer"` → OpenRouter | ✅ **유일한 완전 실시간 경로** |
| 여정 요약 | `SummaryWorker` → `task:"summary"` | ✅ 백그라운드 1회 |
| GPS 주행 | `scripts/demo_route.py`가 `adb emu geo fix` 반복 | — 스크립트 |
| 지역 판정(시·군·구) | 앱 내장 NGII 경계 폴리곤 48곳(`.pgeo`) | ❌ 오프라인 |
| 음악 | APK 번들 m4a 4곡. **15초 고정**(`DEMO_MUSIC_DURATION_MS`), 카탈로그 **순서대로** 선택, **이야기가 시작된 뒤에만** 재생 | ❌ 번들 |

> **답변이 인용할 수 있는 근거는 사용자가 실제로 들은 문단에서만 나온다.**
> `RoomContentContext`가 `playback_attempt ... state='completed'`인 문단의 사실만 모아 보내고,
> 앱이 `context.sourceRevisionIds.containsAll(sources)`로 응답을 검증한다.
> 서버가 새 근거를 끼워 넣으면 답변이 **거부**되므로, 들려줄 내용은 반드시 **팩에 먼저 들어가 있어야** 한다.

## 4. 가장 큰 제약: 답변은 "들은 것" 안에서만 나온다

질문 답변은 **사용자가 그 세션에서 끝까지 들은 문단의 사실**만 근거로 쓸 수 있다.
현재 팩은 출처 17개 / 사실 32개지만, 한 번의 질문이 쓸 수 있는 건 그중 **그때까지 들은 이야기 몫**뿐이다.

- 들은 이야기 안의 질문 → 답변 가능
- 그 밖의 질문 → `unsupported` 또는 "모른다"

그래서 **들려주고 싶은 내용은 먼저 이야기로 만들어 팩에 넣어야 한다.**
대덕구 맛집을 서버가 조회해서 끼워 넣는 설계가 불가능한 이유가 이것이다.

## 6. 알려진 제약

### 플랫폼·설계상 고정

| 제약 | 성격 |
| --- | --- |
| LLM 웹검색 불가 | 도구 없음 + `tool_calls` 응답 거부 |
| 답변 근거는 "들은 문단"만 | 서버 주입 불가 (4장) |
| 음악 4곡 고정·15초·순서 재생 | 무드 선택은 앱 코덱 변경 필요 |
| Gleo로 TTS 대체 불가 | 함수 호출 라우터이며 Action 7초 제한 |

### 에뮬레이터

| 제약 | 대처 |
| --- | --- |
| **오래 켜두면 Car 서비스가 죽는다** | `car_service not ready`가 뜨고 앱에 "차량 연결 상태를 확인하고 있어요"만 보이며 **동행 시작 버튼이 사라진다.** 에뮬레이터를 **재부팅**하면 바로 해결 |
| **권한을 미리 부여하면 안 된다** | `pm grant`로 위치·마이크를 먼저 주면 온보딩이 건너뛰어져 홈 컨트롤이 안 뜬다. 앱에서 "계속하기 → 관심사 → 동행 시작" 순서로 진행할 것 |
| 내비 위치 마커가 주입 위치를 안 따라감 | 에뮬레이터 NMEA 체크섬 버그. 앱 자체 위치 수신은 정상 |
| "경로 탐색 오류" / "경로 안내 재시작" 팝업 | 내비 자체 팝업. 닫으면 됨 |
| 하단 바 아이콘 캐시 | 에뮬레이터가 옛 아이콘 유지 가능 |
| SELinux가 `/data/local/tmp` 쓰기 차단 | 토큰은 `run-as` + `PROVISION_SERVER` 브로드캐스트로 전달 |
| 음성 인식은 Mac 출력 볼륨 85% 이상 필요 | 낮으면 인식 실패 |

### 코드에 하드코딩된 것 (새 데모를 만들 때 반드시 같이 고칠 것)

| 위치 | 내용 |
| --- | --- |
| `BundledStoryCatalog.ASSET` / `SHA256` | 앱이 읽는 팩 **1개**. 팩을 바꾸면 두 상수를 같이 고친다 |
| `DemoVideoMode.REPRESENTATIVE_STORY_IDS` | 영상 모드 대표 이야기 UUID. 새 이야기는 **추가해야 재생된다** |
| **콘텐츠 설치는 1회성** | `adb install`은 데이터를 보존하고 설치기는 기존 팩을 덮어쓰지 않는다. 콘텐츠를 바꾸면 **`pm clear` 필수** — 안 하면 DB에 옛 UUID가 남아 해당 지역 이야기가 **조용히 건너뛰어진다** |
| **끊긴 음악 체크포인트** | 동행을 정상 종료하지 않으면 `musicCheckpoint`가 남고, `PlaybackLookahead`가 첫 이야기를 띄우지 못해 세션 내내 `mode=IDLE target=null` |
| `demo_route.py`의 `STORY_GROUPS` | 시나리오별 `storyGroups`로 덮어쓴다. 없으면 청주를 8초에 통과 |
| `story_lab.py`의 `EVAL_REGIONS` | 새 지역은 코드에 추가. `--region`으로 기존 고정 파일을 보호 |
| 디버그 CA는 **APK에 구워진다** | `prepare` 후 **반드시 리빌드·재설치** |

### 콘텐츠 파이프라인

| 제약 | 대처 |
| --- | --- |
| `approve`는 **교체만** 가능 | 새 지역 이야기는 **`add` 서브커맨드**로 번들에 추가 후 `build_pack --stories` |
