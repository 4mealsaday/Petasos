# 정차 프리뷰의 실제 제어 연결

dev.16의 음악 제어 검증 기록이다. 현재 dev.17의 자동 선택 변경은 아래 추가 항목을 따른다. 권리를 검토한 실제 내부 음악과 **음원 출처** 조회, 음악 정지 후 Play의 위치 재개를 연결했다. 최종 빌드·Lint·JVM 502개/40 suite·호스트 117개·기기 13종·설치 smoke가 통과했다. 실제 화면에서 곡명/작곡자/라이선스 표시와 다른 Activity 전환 후 출처 창 닫힘도 확인했다. [dev.16 결과](./2026-11-08-reviewed-music.md)를 따른다.

이전 dev.15는 최종 privacy·debug 빌드/Lint, JVM 435개·호스트 115개·기기 회귀 12종과 privacy 설치/실행 smoke·최종 기기/소스 확인을 마쳤다. dev.15는 UI 독립 계층에 명시 재생 명령을 추가했고, dev.14는 관심사 자동편성, dev.12는 기록 제어를 추가했다. 기존 색상·글꼴·카드·여백과 기능 제어 배치를 유지한다. 명령은 합성 입력으로 검증했으며 제품 말하기 gate를 열거나 새 입력 UI를 추가하지 않았다. [지원 범위와 증거](./2026-11-08-explicit-playback-commands.md)를 따른다. 최종 제품 UI와 데모 시나리오 설계는 후속이다.

**현재 제품 말하기는 비활성이다.** 아래 입력 흐름은 연결된 구현 계약이며, opt-in privacy 앱에서 확인한 SDK 로그 경로를 제거했지만 별도 Speech 서비스의 원문 로그가 관측됐고 cold/실제 EOF/사람 발화 시간 검증도 남아 있다. 해결 전에는 `supportsLiveInput()` gate가 권한 요청·마이크 시작을 차단한다. [최신 증거와 활성화 조건](./2026-11-08-speech-privacy-verification.md)을 따른다. 합성 probe 성공을 사람 발화 승인이나 제품 활성화로 사용하지 않는다.

`MainActivity`는 레이아웃과 수명주기만 전달한다. `presentation/PlaybackControls`가 MediaBrowser 연결, 선택 목록, 상태 표시, Car UX visibility, 마이크 권한 요청을 담당한다. 콘텐츠·실제 재생·암호화 저장·생성은 Service의 단일 host/runtime에 남는다.

- XML의 첫 상태부터 전체 프리뷰는 GONE이다. CarPolicySource가 현재 연결·제한 상태를 확인하고 `permitsParkedPreview=true`인 경우에만 표시한다. 초기 unknown, 연결 단절, 제한 플래그, distraction-optimization 요구는 모두 정차/연결 확인 안내만 표시한다. [AAOS UX API 조사](../reference/pleos/guides/09-ui-testing-release.md)
- 화면 시작은 MediaBrowser 연결과 읽기 전용 라이브러리 조회만 수행한다. Spinner의 초기 선택이나 목록 갱신은 재생을 시작하지 않는다. 명시적 재생 클릭에서만 표준 setMediaItem/prepare/play를 호출하며 정지·이전·다음도 MediaBrowser 표준 명령이다. 화면 종료는 controller만 해제하고 Service가 소유한 재생을 임의로 다시 시작하지 않는다. [MediaController/MediaBrowser 연결](https://developer.android.com/media/media3/session/connect-to-media-app)
- 말하기는 MediaSession 외부/custom command로 제공하지 않는다. 같은 프로세스의 현재 host와 보이는 UI 조건을 사용한다. RECORD_AUDIO 권한은 말하기 클릭에만 요청한다. 허가 결과는 안내만 갱신하고 **다시 말하기를 누르기 전에는 마이크를 시작하지 않는다**. 거부 시에도 재생 기능은 유지한다. [권한 요청 원칙](https://developer.android.com/training/permissions/requesting)
- 아직 재생 세션이 없는 IDLE에서도 명시적 말하기를 허용한다. host는 복구 완료 후 필요한 세션만 만들고 재생 명령 없이 Talk를 전달한다. TALK_PENDING/PROMPT/LISTENING에서는 말하기를 다시 눌러 취소할 수 있고 GENERATING/ANSWERING 중 재입력은 허용하지 않는다. 실제 마이크 시작 직전에 OS 권한·보이는 화면·차량 마이크 전원 정책을 다시 확인한다.
- onPause/onStop에서 host의 visible-input gate를 내리고 진행 중 입력 상호작용을 취소한다. UX 제한이 새로 적용되어 프리뷰가 숨겨지는 경우도 동일하다.
- 재생 제어에는 검토된 공개 이야기 제목과 고정 상태 문구를 표시한다. dev.12 기록 화면은 저장된 요약과 사용자가 입력한 관심사도 표시하며 숨겨질 때 이 텍스트를 지운다. 최종 발화·임시 생성 응답 원문·정밀 좌표·오류 원문·인증값은 표시하지 않는다.
- 위치 기록 설정은 재생 클릭과 독립이다. 앱 시작이나 Media Play가 vehicle.location_enabled를 자동으로 켜지 않는다.

`car-policy-ui` 기기 probe는 실제 Car UX 읽기/해제와 합성 제한별 전체 프리뷰 visibility를 확인한다. 차량 상태 변경, 마이크, 실제 재생은 호출하지 않는다. 빌드·기기 실행 결과는 통합 개발 기록을 따른다.

## dev.11 기능 추가

기존 디자인을 유지하며 **새로 만들어 듣기** 버튼만 추가했다. 명시적 정차 UI 요청에 한해 설치된 공개 근거로 새 대본을 생성·저장·재생한다. 준비 중 선택/재생/다음/이전을 막고 정지는 유지하며, 화면 비가시화와 권한 차단은 대기 작업을 취소한다. 코드·검증·재실행 방법은 [dev.11 기록](./2026-11-07-story-resume-generation.md)을 따른다. 사람 마이크는 계속 비활성이다.

## dev.12 기록 제어

`TripControls`와 `TripResultsFormatter`를 별도로 두고 `view_trip_controls.xml`·`strings_records.xml`에서 배치와 문구를 관리한다. 위치 기록 동의 ON/OFF와 Pleos 위치 권한 요청은 별도 동작이다. 조회는 설정 행이나 이동을 만들지 않으며 관심사만 처음 저장할 때 위치는 OFF다. 활성 이동에 명시 동의와 플랫폼 권한이 모두 있을 때만 기록을 시작한다. 종료 중에도 동의 철회는 허용한다.

최근 이동 20개에서 결과를 선택하며 요약·카드 상세는 각각 최대 50개, 전체 집계는 제한 없이 읽는다. 상세 표시 제한을 안내하고 출처가 철회된 공개 콘텐츠나 임시 대화 payload를 가져오지 않는다. 기록 화면도 Car UX가 허용된 정차 상태에서만 표시하며 비가시화되면 관심사·요약 텍스트를 지운다.

**이동 종료**는 Play/다음/이전/새 이야기 준비를 차단하고 실제 정지 ACK와 저장을 기다린다. 10초 안에 확인되지 않으면 미확정으로 안내하며 성공을 만들어내지 않는다. 성공 후에는 같은 host의 다음 재생이 새 이동에서 시작한다. 표준 미디어 정지는 계속 현재 이동을 유지한다. 실제 제품 공개 이야기 TTS 정지·종료 저장·다음 이동 시작과 읽기 무변경을 기기에서 검증했다. [dev.12 결과와 APK 경계](./2026-11-08-trip-records.md)를 따른다. 사람 마이크·위치 동의 변경·모델 호출·주행 검증은 이번 시험에 포함하지 않았다.

dev.13 opt-in privacy의 기기 회귀 19종과 설치 smoke를 통과했고, 최종 app-trip-lifecycle도 같은 제품 이동 종료·새 이동 경계를 다시 확인했다. 별도 합성 음성 8회의 기능 PASS는 서비스 로그 해결이나 사람 발화 검수가 아니다. 현재 마이크 차단과 Virtual Console 보류를 유지하며 공식 설정/수정 버전 확인을 기다린다. 문의 초안은 미전송이고 최종 화면 디자인은 별도 논의한다.

## dev.14 저장된 관심사와 자동편성

화면 외형이나 버튼 구조를 추가로 바꾸지 않고 기존 관심사 저장을 편성에 연결했다. 저장한 keyword와 설치 콘텐츠의 interest tag가 정확히 일치할 때만 관심 후보가 되며, 위치가 unknown이어도 이 후보는 사용할 수 있다. 관심사를 저장한다고 재생을 시작하거나 위치 동의를 켜지는 않는다. 현재 재생 의도와 문단/곡 경계는 Coordinator가 관리한다.

관심·위치 설정을 변경하기 시작하면 대기 중 자동 offer의 권한을 즉시 철회하고 worker 저장 후 새 상태로 다시 고른다. 이미 시작한 일반 이야기를 관심 설정이나 지역 변경만으로 끊지는 않는다. 한 문단이라도 완료된 story와 완료 문단의 stable fact 이력, 현재 세션 시작·명시 건너뛰기 이력은 자동 반복을 막지만 사용자가 직접 다시 고르는 재생은 허용한다.

이야기를 정상 완료했거나 이미 음악을 시작한 뒤의 다음 자동 이야기에는 음악의 정상 완료가 필요하다. 미완료 이야기에서 명시적으로 Next를 누르면 다른 허용 후보를 선택할 수 있다. dev.14 당시에는 제품 음악 카탈로그가 비어 대기했다. dev.16에서 권리를 검토한 실제 음원 공급을 연결했으며 음악의 정상 종료 경계는 유지한다. 외부 대본을 자동 생성하거나 실제 지역·랜드마크 정책을 활성화하는 기능과도 구분한다. 시작/Next 경합까지 반영한 최종 privacy 빌드·Lint, JVM 393개/31 suite·호스트 112개·기기 12종, 기본 debug 호환·privacy smoke·최종 기기/소스 확인까지 통과했으며 [dev.14 결과](./2026-11-08-automatic-story-planning.md)를 따른다.

## dev.16 내부 음악과 출처

기존 외형을 유지하며 **음원 출처** 버튼을 추가했다. 읽기 전용 창에서 곡명·작곡자·앨범·저작권·라이선스·공식 원본과 변경 여부를 확인한다. 파일 설치/검증은 host worker가 처리하며 화면이 숨겨지거나 host가 바뀌면 창을 닫고 늦은 결과를 버린다.

음악을 정지한 뒤 **재생**은 저장된 음악 위치를 이어간다. 실제로 스피너 선택을 바꾼 경우에만 그 이야기를 명시 선택한다. 이야기 목록이 비어도 사용 가능한 내부 음악이 있으면 재생할 수 있다. 명시 Play 이전에는 출처/목록 조회나 prepare만으로 세션과 오디오를 시작하지 않는다. 현재 1곡이며 추가 음원은 권리·원본 크기/SHA·출처를 검토한 번들로 넣는다. Spotify 로그인/SDK는 연결하지 않았다. [dev.16 구현과 최종 증거](./2026-11-08-reviewed-music.md)를 따른다.

## dev.17 기본 자동 편성

선택 목록의 첫 항목은 **지역 이야기 자동 편성**이다. 사용자가 이야기를 새로 선택하지 않았다면 일반 재생은 자동 후보·기존 checkpoint를 사용한다. 첫 설치 이야기나 이전 이동의 목록 값을 새 명시 재생으로 해석하지 않는다. 설치 이야기를 직접 선택하면 기존 명시 재생을 유지하고, **새로 만들어 듣기**는 실제 이야기를 선택했을 때 활성화된다. 음악 위치 재개와 UX 제한/비가시화 정책은 유지한다. 길이 기반 편성 및 실제 경로 입력 제한은 [dev.17 기록](./2026-11-08-duration-aware-regional-planning.md)을 따른다.
