## 좌표 검토에서 확인한 것

- 원 후보 JSON의 SHA를 기존 검토 기록과 대조했다. 6개 모두 contentId·이름·주소·좌표 문자열이 inventory와 일치한다. 원 파일의 `pending`·허용값 false는 그대로다.
- 첫 두 장소는 검색 응답과 상세 응답에서도 contentId·이름·주소·좌표가 일치한다. **동일 제공자의 두 작업을 대조한 것**이며 독립 측량·독립 출처라고 표현하지 않는다.
- [저장한 공식 TourAPI schema](../reference/public-data/tourapi.openapi.json)의 `mapx`/`mapy` WGS84 경도/위도 설명을 확인했다. 최초 수집 metadata와 schema SHA를 재확인하고, 사용한 JSON pointer를 private evidence에 보존했다.
- [공식 데이터 카탈로그](https://www.data.go.kr/catalog/15101578/openapi.json)를 다시 읽어 이용허락범위 제한 없음과 사진의 1·3유형 별도 안내를 확인했다. 두 새 출처는 **이름·주소·좌표 원문 필드를 텍스트로 보존한 메타데이터**만 허용한다. 엑스포의 `cpyrhtDivCd=Type3`도 원값으로 보존하며 이미지·설명문 전체·음성은 포함하지 않았다.
- 실제 APK의 pinned NGII `.pgeo` bytes·크기·SHA를 확인한 뒤 정적 point-in-ring 포함을 검사했다. 용인시/기흥구, 천안시/동남구의 겹침도 그대로 기록했다. 이는 Python/Shapely의 자료 대조이며 Android 판정기·히스테리시스 검증 결과가 아니다.

좌표의 검토 범위는 **공급자가 해당 contentId에 지정한 대표점**이다. 실제 건물 경계, 도로에서의 가시성, 차량 진입 위치, 측량 오차는 확인하지 않았다. API 설명 중 높이·운영시간·미디어파사드 같은 현재 운영 정보는 이번 범위에 없다.

기존 source review는 텍스트 사실만 승인하고 좌표를 제외했으므로 이를 암묵적으로 확장하지 않았다. 두 새 metadata source는 다른 source ID/revision으로 그 필드 범위를 구분한다. `license.scope=text`는 현행 bundle의 텍스트 메타데이터 계약이며, 이미지 권리를 뜻하지 않는다. `allowDisplay=true`, `allowDistribution=true`, **`allowGeneration=false`**다. 기존 12개 source 및 18개 fact는 변경하지 않았다.

## 실제 연결에 남은 구현과 정책 자료

현행 TX-05는 place를 추가할 수 있지만 `landmark_policy_json`은 null로 설치한다. 기존 story의 `placeId=null`을 바꿔 재설치하면 immutable 비교에서 거부한다. `RoomLandmarkCandidates`는 현재 `story.place_id`와 정책이 있어야 읽으므로 **이 초안을 설치하는 것만으로 자동 랜드마크가 나오지는 않는다**.

다음 구현에서는 검토된 story↔place 연결을 명시적으로 설치하는 계약이 필요하다. 기존 story/fact와 청취 이력을 유지하는 **별도 binding revision 및 현재성 검사**가 가능한 최소 방향이다. 실제 schema·API는 아직 확정하지 않았다. canonical story 행을 임의 SQL로 변경하거나 이야기 ID를 복제하는 방식은 사용하지 않는다. 설치기는 좌표 출처·association fact·정책을 함께 고정하고 atomic install, exact reinstall, 충돌·철회·generated-version omission을 검사해야 한다.

[DATA-11](../Petasos_데이터_API_계약.md)과 [랜드마크 정책 계약](reviewed-landmark-policy.md)을 채우려면 다음 자료가 필요하다.

1. 두 공식 대표점 주변 **시연 도로 경로**와 접근·최단 통과·이탈 구간. 공원 대표점이 도로와 떨어질 수 있으므로 직선 반경만 크게 만드는 방식으로 해결하지 않는다.
2. 검토할 반경·cooldown에 대해 감소·정지·오차 중첩·통과·반대방향·재접근·위치 단절을 재생하는 자료와 결과. 공식 도로 geometry/ETA, 합성 잡음·시간 시퀀스, 실제 Android 측정은 각각 표시한다. 합성 입력이 실제 주행 측정으로 둔갑하면 안 된다.
3. 정책 version·품질 어댑터 version과 각 값의 근거. 정책 verifiedAt은 좌표 source와 association fact 검토 시각보다 빠를 수 없다. 근거가 없는 숫자·default policy·승인 JSON은 만들지 않았다.
4. 같은 장소에서 S01 또는 S10을 선정한 이유와 전역 완료 story/fact 제외, 음악 이후 경계, 대화 중 지나친 후보의 영구 만료를 함께 확인한다.

첫 통합 검증은 **내비가 명시적으로 INACTIVE인 CurrentPosition**으로 한정한다. disposable Room에서 exact 자료 설치·재설치·철회와 테스트 위치 시퀀스를 먼저 확인하고, 기기에서는 기존 동의와 유효한 측정 두 점·실제 출력 경계를 확인한다. 테스트 전용 입력을 사용했다면 합성 위치임을 결과에 표시하며 실제 차량 수락 시험 완료라고 표시하지 않는다.

ACTIVE 내비는 현재 Host에서 `Unavailable`이다. 보조 NAVER 경로가 반환되거나 그 선이 장소 근처를 지난다는 이유로 `OnRoute`를 부여하지 않는다. Pleos 활성 경로 membership을 증명할 공식 입력·계약은 별도다. 첫 두 장소의 데이터 준비와 CurrentPosition 검증을 이 문제의 해결까지 보류할 필요는 없다.

현재 단계에는 새 키·계정이나 사용자의 장소 선택 답변이 필요하지 않다. 공식 좌표 선별과 자료 대조는 개발 검토로 완료할 수 있었다. 사용자에게 필요한 실제 기기·발화·주행 검증이 생기면, 테스트 전용 결과와 구분해 구체적인 시험 절차를 안내한다.
