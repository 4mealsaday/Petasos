# 지역 판정 정책의 최초 확정과 현재 권한

작성일: 2026-11-08. 구현·검증 버전: `0.8.0-dev.24`. 최종 설치·실행 확인: 2026-11-08 13:17:51 UTC.

## 기준과 범위

[Notion 데이터/API 계약](https://app.notion.com/p/40fcf80747f28133bc02fb1176961b0e)의 DATA-11·INV-03·8.7과 [동작 명세](https://app.notion.com/p/40fcf80747f281e0bde7d1638339550f)의 COL-01을 재확인했다. 정책 수치는 검토한 시연 자료에서 정하며 검증 전에는 자동 판정에 사용하지 않는다. 기존 SQL·Room schema 2, 원본 dataset version, 지역 ID, 과거 수집 근거는 유지한다.

[설계 검토안](./2026-11-08-region-policy-install-plan.md)의 두 해석 중, 아직 DATA-11 정책이 없는 정확한 초기 pending 행을 최초 1회 확정하는 방식을 채택한다. 이는 명세에 전이 절차가 명시돼 있다는 주장이 아니라, 미검토 상태와 판정 당시의 불변 근거를 함께 보존하기 위한 구현 해석이다. 최초 확정은 검토 시각이 NULL이고 해당 revision의 수집 proof가 없으며 기하 원본이 변하지 않았을 때만 가능하다. 이후 정책 내용·검토 근거·검토 시각은 덮어쓰지 않는다. 정책 수정본과 재검수는 별도 revision 계약이 필요한 후속 범위다.

실제 NGII 264개 지역 정책과 가거도 콘텐츠의 지역 연결은 이 개발만으로 승인하지 않는다. 현재 사용자의 위치 기록 동의·권한도 변경하지 않는다.

## 책임 분리

- 순수 정책 codec은 대상 revision, manifest·geometry SHA, DATA-11 필드, 검토 시각·근거·증거 SHA를 검사한다. 정책 기본값은 제공하지 않는다.
- [고정 정책 bundle](./reviewed-region-policy-bundle-v1.md)은 APK 자산과 별도 코드 SHA pin을 검사한 뒤 worker에서 단일 설치 batch로 전달한다. 현재 승인 목록은 비어 있으며 실제 임계값을 포함하지 않는다. 근거 파일의 진실성은 오프라인 자료 검토 책임이다.
- geometry metadata는 기존 pending JSON과 같은 원본 봉투를 생성하고, 정책 확정 여부와 독립적으로 기하 동일성을 비교한다.
- Room 정책 설치기는 정확한 초기 상태에서 첫 확정을 원자적으로 수행한다. 같은 재설치는 no-op이며 다른 정책, 격리 기하, 변조된 원본, 철회 후 재설치는 거부한다.
- 공통 정책 reader는 현재 출처 권리와 `sourceVerifiedAt ≤ policyVerifiedAt ≤ now`를 검사한다. 기존 최소 DATA-11 형식과 기하 봉투 형식을 구분하며, 손상된 새 봉투를 기존 형식으로 해석하지 않는다.
- 지역 확정 결과는 region ID와 함께 판정 revision·정책/출처 fingerprint를 전달한다. 편성 및 최종 worker 검증에서 현재 유효성을 다시 확인하고, main에서는 메모리에 있는 철회 상태만 확인한다.

지역 정책의 철회는 자동 지역 선택 권한을 없앤다. 기존 카드·proof를 삭제하거나 원시 위치 권한, 수동·관심사 이야기, 자체 정책으로 검증하는 랜드마크의 권한으로 확대 적용하지 않는다. 새로운 런타임 정책 편집 UI나 원격 승인 API는 추가하지 않는다.

## 검증 결과

[최종 집계](../../artifacts/milestone-24/verification.json)에 전체 결과와 APK 해시를 기록했다.

- JVM 855개/63 suite, 호스트 162개: 실패·생략 0.
- 최종 privacy 앱·검증 APK 빌드와 Lint, 알려진 앱 SDK 로그 sink 정적 검사 PASS. 별도 SpeechService의 원문 로그 해결을 뜻하지 않는다.
- 같은 최종 APK로 기기 10종 PASS: 지역 정책 설치, 기하 저장소, 위치 저장소, 자동 편성, 지역 콘텐츠, 랜드마크, 세션 복구, 미디어 세션, 차량 UX, 실제 위치 수신.
- 새 정책 probe는 폐기 DB에서 최초 설치·동일 재설치·다른 검토 거부·후속 항목 실패 시 전체 rollback·철회 후 재설치 거부·catalog 재로드·기존 proof 보존을 확인했다. 고정 빈 제품 catalog를 두 번 읽어 264개 exact pending JSON과 NULL 검수 상태가 유지되는 것도 확인했다. 합성 수치와 좌표는 제품 정책 검수 결과가 아니다.
- 실제 위치 수신과 Activity 닫기→저장 중단→재열기 후 새 구간 수신 PASS. Home/task 이동은 Activity를 숨기지 않아 Home/background 수용 검증으로 간주하지 않는다. 위치 동의·권한은 변경하지 않았다.
- 위 10종과 smoke 통과 후 마지막 상태 확인 중 에뮬레이터가 QEMU thread hang과 함께 종료 코드 139로 멈췄다. 원인은 확정하지 않았으며 앱 크래시로 기록하지 않는다. 기존 사용자 데이터를 보존해 재시작한 뒤 정책·실제 위치 2종과 설치/실행 smoke를 다시 통과했다. 총 10종/12회는 같은 APK 쌍이다.
- 소스 577개는 최종 빌드 이후 일치하며 기존 기하 자산과 Room schema 2는 변하지 않았다. 최종 설치 해시 일치·dev.24 전면 실행·기존 localhost reverse·HTTPS health 200을 확인했다.

중간 빌드 845개 결과는 최종 합계에 더하지 않는다. 서버 코드·모델/공공 API·사람 발화·Virtual Console·실차 경계 시험은 이번에 실행하지 않았다. 기본 debug 빌드/Lint도 별도 재실행하지 않았다.

## 실제 활성화에 남는 근거

시연 경로의 경계 왕복·오차·단절·오래된 표본에 대한 검수 자료가 필요하다. dev.23의 실제 에뮬레이터 위치 수신은 이 임계값을 검증한 결과가 아니다. 전체 도로 경로·구간 ETA, 실제 지역 콘텐츠와 랜드마크 정책 공급도 별도다. Virtual Console과 사람 마이크 보류는 유지한다.
