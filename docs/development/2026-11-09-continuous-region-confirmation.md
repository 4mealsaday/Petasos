# dev.27: 빈도에 독립적인 지역 확인 구간

2026-11-09 KST. Debug JVM **969개/75 suite**, privacy 앱/검증 APK 빌드·Lint·알려진 앱 SDK 로그 sink 정적 검사 PASS. 동일 최종 APK 기기 검사 **6종/7회**와 설치·실행 smoke PASS다. [집계](../../artifacts/milestone-27/verification.json).

## 변경

기존에는 최근 N개 위치만 조회해 최소 유지시간을 검사했다. N=3/2초 조건에서는 1Hz 수신이 통과해도 2Hz·5Hz의 최근 세 점은 계속 2초보다 짧아 적립이 누락됐다. `RegionConfirmation.proof()`는 같은 구간의 최신 위치부터 역순으로 검사하여 최소 개수와 시간을 처음 함께 만족하는 연속 suffix를 반환한다. SQL 조회와 proof 모두 100개가 상한이며, 무효 점·다른 지역·시계 변경·중복 측정·시각 역행을 건너뛰지 않는다.

판정은 순수 `location` 모듈, 원자적 저장은 `RoomLocationStore`, 표본 수집과 경계 자료는 기존 어댑터에 유지했다. Android 측정의 원래 단조 시각도 증가해야 하므로 epoch만 달라진 캐시 중복은 새 근거가 되지 않는다. historical point를 현재 wall clock으로 다시 stale 판정하지 않는다. 기하 검사 후 동일 정책·출처·계층 권한을 다시 확인하며, 확정의 마지막 point ID는 방금 저장한 위치여야 한다.

새 카드의 rule은 `region-confirmation-v2`/`region-confirmation-hierarchy-v2`로 구분한다. 이미 적립한 카드와 proof는 수정하지 않는다. 같은 지역의 현재 위치 권한은 갱신할 수 있지만 과거 획득 근거를 갈아 끼우지 않는다. 정책 catalog는 여전히 0개다.

## 후보 비교

[검증 기록](region-policy-demo-validation.md)의 v2 자료는 1m 변환 오차 여유를 제품과 동일하게 차감한다. 27개 후보·9개 지역에서 양성 **729개/누락 0**, 음성 **2,673개/오판정 0**이다. 동일 v2 자료에서 고정 N개 창을 쓰는 대조군은 양성 270개를 놓쳤다. v1 원본도 보존하며 서로 동일 fixture라고 주장하지 않는다. 정지 내부점·경계 왕복 중심의 합성 자료이며 실제 차량 위치 정확도나 도로 ETA를 검증한 결과는 아니다. 이동하는 경계 통과 시연 자료와 후보 선택 근거를 추가한 뒤 해당 지역만 검토한다.

## 기기 검사 보완

`ProductLocationProbe`는 복귀 이후 새 segment의 수신량과 세션 누적량을 구분한다. 복귀 main/worker 응답과 cleanup 단계 시간을 고정 코드·숫자로 남기며 기존 15초 관측 한도를 늘리지 않았다. dev.26 실패는 보존한다. `ProductPlaybackProbe`는 Activity를 띄우지 않는 미디어 서비스 검사이므로 기존 위치 동의 ON을 이유로 시험을 거부하지 않는다. 대신 동의 값·버전·수정시각이 그대로이고 실제 위치 구간이 생성되지 않았음을 확인한다. 마이크·생성 요청과 사용자 설정 변경은 없다.

## 기기 결과

- 실제 Room의 5Hz·N=3·2초 합성 사례에서 무효 점 뒤 10개(1.8초)는 보류하고, 11개(2초)에서 정확한 point ID 11개로 카드/proof를 저장했다. 이후 현재 위치 권한은 바뀌어도 획득 proof는 유지됐다. 기존 위치 저장·Android 계약·지역 계층 회귀도 PASS다.
- 실제 위치는 에뮬레이터 재시작 후 **23,702ms**, 실제 TTS 검사 뒤 재확인 **18,454ms**에 PASS였다. 각 복귀에서 새 segment 1개·표본 2개·유효 UPDATE 1개를 확인했다. 종료 후 활성 segment는 0개였다. Home/background는 셸이 화면을 숨기지 않아 미검증이며 실제 Activity 닫기/재열기로 구분한다.
- dev.26의 복귀·cleanup 실패는 재현되지 않았지만 원인을 확정하거나 수정했다고 주장하지 않는다. 제품 위치 소스 코드는 이번에 변경하지 않았으며 원본 실패는 유지한다.
- 실제 제품 MediaBrowser→Host→TTS의 시작·문단 완료 저장·Stop이 **4,462ms**에 PASS였다. 기존 위치 동의가 보존되고 위치 구간·마이크·모델 요청은 생성되지 않았다. 이 검사는 설치된 공개 이야기의 최소 한 문단이며 **패키지 10개 전체의 청취·길이 검수는 아니다**.

사용자 DB·청취/이동 이력·권한·동의는 보존했다. 재생 검사에서 발생한 정상 청취 기록은 지우지 않았다. 사람의 발화, Virtual Console, 주행 상태 변경, UI 디자인 변경은 하지 않았다.
