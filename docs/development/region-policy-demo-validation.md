# 지역 정책의 시연 자료 검증

상태: 2026-11-09, 후보 비교 하네스 실행 PASS. 27개 후보·9개 지역·양성 729개/음성 2,673개에서 음성 오판정은 0개였다. 이는 정책 승인이 아니다. 실제 승인 policy asset은 **0개**로 유지한다.

## 명세와 검증 경계

[COL-01](../Petasos_동작명세.md)은 경계 부근 확인 횟수·거리·시간을 **시연 데이터로 검증한 RegionPolicy**에서 가져오도록 한다. [DATA-11](../Petasos_데이터_API_계약.md)은 각 값을 **시연 경로 자료로 채우고 verified일 때만** 자동 판정에 사용하도록 한다. 이 단계의 정책 후보 검토에 실주행이 필수라는 조건은 없다. 실제 기기의 수신 의미와 시연 자료의 판정 검토는 각각 증거를 남긴다.

기존 `RegionConfirmationTest` 6개는 연속 순번, 품질·adapter, 측정/수신 시각 증가, clock scope, 경계 거리에 정확도 반영, 중첩·다른 dataset·경계점 거부를 확인한다. 수신 단절은 `RegionConfirmation` 자체가 판정하지 않는다. `LocationRecorder`가 구간을 닫고, `RoomLocationStore`가 같은 구간의 최근 행만 조회해 단절 전후를 분리한다. 따라서 정책 비교에도 normalizer·recorder·판정 함수를 함께 사용한다.

## 최소 하네스

[RegionPolicyDemoHarnessTest](../../app/src/test/java/com/petasos/app/location/RegionPolicyDemoHarnessTest.kt)는 기존 JUnit 실행 환경을 사용한다. 제품 코드·Room·사용자 DB·기기 위치·네트워크·승인 자산을 변경하지 않는다. 메모리 store는 현재 구현의 **같은 segment 최근 N개 행**을 판정 함수에 전달한다. SQL 트랜잭션·중복 ID·권한 철회는 기존 저장소 검사 범위다.

- 입력: 기존 SHA로 고정된 NGII 264개 catalog와 5개 계층 관계. 실제 좌표열을 단순화하지 않는다.
- 양성 기준: 독립 GEOS oracle의 내부 점. 원래 5개 콘텐츠 묶음에 대응하는 leaf 9개(`11140`, `41461`, `41463`, `41465`, `41550`, `44131`, `44133`, `30110`, `30200`)를 사용한다. 실제로 해당 지역을 통과했다는 자료가 아니다.
- 경계 기준: SHA를 확인한 실제 packed geometry의 꼭짓점. 그 점에 ±0.00001도 위도 오차를 더한 왕복 관측도 사용한다. 실제 경계에서 1.2m 미만의 합성 오차를 주고 보고 정확도는 5m로 둔다. 이는 보고 반경 안의 오차 모델이며 Android 정확도를 확정 오차 상한으로 주장하지 않는다.
- 후보 27개: 확인 개수 `2/3/5` × 최소 유지 `0/1000/2000ms` × 추가 경계 여유 `5/10/20m`. 모두 Android 표준 adapter·EPSG:4326이며 기본값이나 권장 승인값이 아니다.
- 양성: 1/2/5Hz에서 6초간 충분히 내부에 머무는 합성 관측. 최초 판정 지연과 누락을 그대로 기록한다.
- 음성 11종: 정확한 경계, 반경 안 오차의 경계 왕복, 한 점의 짧은 통과, 중간 무효 점, 오래된 측정, 같은 측정의 반복 수신, 정확도 초과, mock, NoLocation, 수신 공백, 수신 시각 역행.

출력은 dataset/manifest/hierarchy identity, 지역 코드, 후보 설정, 사례 수, 음성 사례의 오판정 수, 양성 사례의 누락·최초 판정 지연이다. 좌표·원문 경로는 출력하지 않는다. 반복되는 합성 점의 검증된 경계 결과만 최대 128개 메모리 항목으로 재사용한다. 제품에서 경계 권한이나 파일 검증을 캐시하도록 바꾸는 기능이 아니다.

루트에서 기존 JDK/Gradle 환경으로 다음 selector를 실행한다. 출력 경로는 이 저장소의 `artifacts/` 아래 JSON으로 제한한다. 테스트가 up-to-date이면 기존 결과로 오인하지 말고 실제 실행 여부를 확인한다.

```sh
PETASOS_REGION_POLICY_REPORT="$PWD/artifacts/region-policy-demo/candidate-metrics.json" \
  ./gradlew :app:testDebugUnitTest \
  --tests com.petasos.app.location.RegionPolicyDemoHarnessTest
```

이 하네스는 후보별 음성 사례 오판정 0과 최소 유지 0 후보의 양성 대조군을 검사한다. 나머지 양성 누락은 결과에 남기며, 비교 결과가 나쁘다고 후보 시간을 자동으로 낮추거나 verified 정책을 생성하지 않는다. 네이버의 공식 공개 경로를 입력에 더하는 일은 이후 경로별 coverage 검토다. 이번 하네스는 네이버 경로나 실제 ETA를 사용했다고 표시하지 않는다.

## 먼저 확인할 제품 동작

현재 함수는 `points.size == consecutiveSamples`이고 Room도 그 개수만 조회한다. 예를 들어 `N=3`, 최소 유지 2초이면 1Hz의 최근 세 점은 2초를 덮지만 2Hz에서는 1초, 5Hz에서는 0.4초뿐이다. 충분히 오래 내부에 머물러도 최근 고정 N개 창은 계속 짧아 양성이 누락될 수 있다. 이는 경계 여유를 조정할 문제가 아니다.

결과를 확인한 후 **최소 확인 개수와 최소 유지시간을 동시에 만족하는 제한된 연속 창**을 제품 코드에서 선택하는 방향을 검토한다. 같은 segment 안에서만 한정된 행을 읽고, 무효 점·다른 지역·시각 역행을 건너뛰지 않아야 한다. 조회 상한과 지원할 표본 주기·최소 유지시간의 관계도 결과에 남긴다. 제품 수정 뒤 같은 후보·동일 fixture를 재실행하여 누락 감소와 음성 오판정 0을 함께 확인한다.

후보 비교 → 제품 결함 수정 → 동일 자료 재검증 → 대상 지역별 정책 검토 기록 순서다. 검증하지 않은 264개 전체를 승인하거나, parent 도시 관계를 방문 카드로 승격하지 않는다. 최종 정책 검토는 실제 경계·계층 해시, 후보 값, 자료/시나리오 버전, 결과 해시와 한계를 묶어 별도로 확정한다.
