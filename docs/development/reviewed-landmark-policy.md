# 검토한 랜드마크 정책과 이야기 연결

이 계약은 [v0.8 DATA-11](../Petasos_데이터_API_계약.md)의 기존 `place.landmark_policy_json`을 읽는 앱 내부 검토 형식이다. DATA-11의 접근 반경·통과 규칙·방향 규칙·재안내 간격·정책 버전을 유지한다. Room 테이블, 콘텐츠 bundle v1/v2, 이야기·사실 ID와 생성 API를 변경하지 않는다. 실제 장소의 정책이나 좌표를 승인하거나 자동으로 채우는 기능은 포함하지 않는다.

현재 TX-05는 `story.placeId`가 함께 설치한 장소를 참조하는지 확인하고 기존 행의 임의 덮어쓰기를 거부한다. 그러나 이 참조와 문단의 사실 목록만으로는 어떤 사실이 이야기와 장소의 관계를 증명하는지 알 수 없다. 따라서 장소에 이야기를 연결했다는 이유만으로 랜드마크 자동 후보가 되지 않는다. 검토 정책은 **해당 장소에서 자동 안내하도록 선정한 하나의 `storyId`와 그 연결을 증명하는 `associationFactRevisionId`**를 명시한다. 사실의 의미와 연결의 적절성은 자료 검토 대상이며 런타임이 문장·장소명·좌표에서 추론하지 않는다.

## 정책 필드

JSON 객체에는 아래 11개 키가 정확히 있어야 한다. 누락·추가·중복 키와 잘못된 타입은 거부한다. 수치의 문자열·소수·지수 표기를 정수로 변환하지 않는다.

| 키 | 요구 조건 |
| --- | --- |
| `approachRadiusMeters` | 0보다 큰 JSON 정수. 실제 값은 경로 자료로 검토한다. |
| `passedRule` | `increasing_distance_after_approach` |
| `directionRule` | `decreasing_distance` |
| `cooldownMs` | 0 이상 JSON 정수 |
| `policyVersion` | 공백이 아닌 문자열, 최대 200자 |
| `qualityAdapterVersion` | 검토한 위치 의미 어댑터 버전. 공백이 아닌 문자열, 최대 200자 |
| `reviewStatus` | `verified` |
| `verifiedAt` | 검토 시각의 epoch milliseconds 정수. 현재 시각 이후일 수 없다. |
| `reviewBasis` | 해당 장소의 좌표·접근 정책·이야기 연결 근거를 함께 검토한 설명. 공백이 아닌 문자열, 최대 4,000자 |
| `storyId` | 이 장소에서 자동 안내하도록 검토한 설치 이야기 ID |
| `associationFactRevisionId` | 설치된 `kind=verified_fact` 연결 근거 revision ID. `tradition`은 연결 근거로 쓰지 않는다. |

두 ID는 기존 콘텐츠 ID 규칙 `[A-Za-z0-9][A-Za-z0-9_.:-]{0,127}`을 따른다. 현재 구현은 장소당 한 개의 선정 이야기를 승인한다. 동일 장소에 여러 자동 이야기를 승인하는 계약은 별도 확장 대상이며 이야기·장소 ID를 복제해서 우회하지 않는다. 접근 수치나 실제 품질 어댑터 버전에는 기본 승인값이 없다.

## 현재 증거 검사

정책 검토는 현재 `place` 행의 좌표와 좌표 출처, 이야기와 장소를 연결하는 사실을 함께 대상으로 한다. 좌표 출처의 `verified_at`과 연결 사실의 `verified_at`은 모두 0 이상이어야 하고 정책 `verifiedAt`보다 늦을 수 없다. 정책 시각은 현재 시각 이하여야 한다. 좌표는 위도 −90~90, 경도 −180~180 범위의 유한한 값이어야 하며 두 값과 좌표 출처가 모두 있어야 한다. TX-05의 기존 WGS84 검증을 재해석하거나 다른 좌표계로 추정하지 않는다.

좌표 출처와 연결 사실의 모든 출처는 현재 `review_status=verified`, 0 이상이며 미래가 아닌 검토 시각, `allowDisplay=true`, `allowDistribution=true`를 만족해야 한다. 출처가 없는 사실은 사용할 수 없다. 이 읽기 경로는 로컬에서 준비한 이야기를 선정하므로 `allowGeneration=false`만으로 제외하지 않으며, 생성 권한을 새로 부여하지도 않는다.

`story.place_id`는 정책을 가진 장소를 가리키고 정책 `storyId`는 실제 후보 이야기와 일치해야 한다. 다른 이야기를 그 장소에 다시 연결해도 자동 승인이 생기지 않는다. 연결 근거는 최신 문단의 사실 목록과 별도로 매번 읽는다. 생성된 새 버전이 그 사실을 문단에서 생략해도, 원래 연결 사실의 종류·검토 시각·내용·출처·권한 변경은 현재 후보를 철회하거나 기존 후보의 fingerprint를 무효화한다. 이 방식은 [지역 연결의 독립 근거 검사](./regional-content-bundle-v2.md)와 같은 원칙을 따른다.

일반 자동 이야기와 공유하는 최신 published 버전·본문 해시·현재 이용 권한·전역 완료 story/stable fact 이력·세션 제외 조건도 적용한다. 장소·정책·좌표 출처·연결 사실·연결 출처·현재 대본 근거를 모두 fingerprint에 포함한다. 저장소의 후보 적격성은 위치 권한이나 접근 판정 승인이 아니며, 실제 위치 품질·신선도·경로 맥락·출력 직전 재검사를 별도로 통과해야 한다.

## 범위와 비용

`RoomLandmarkCandidates`는 읽기 전용이다. 정책 설치 도구나 자동 승인 경로를 추가하지 않는다. 기존 실제 콘텐츠의 NULL 좌표·정책과 위치 동의는 유지한다. 합성 Room probe가 쓰는 정책·좌표·SQL 변경은 폐기되는 테스트 DB에만 적용하며 실제 검토 자료가 아니다.

공간·접근 판정 전에 이야기 ID 순으로 결과를 자르지 않는다. 정책이 NULL인 장소는 SQL 단계에서 제외하며, 검토 후보의 조회와 출력 직전 `isCurrent`는 현재 자료를 다시 읽는다. 선택한 주요 장소 수가 작은 P0 범위에서 캐시를 도입하지 않았다. 향후 데이터가 늘면 공간 필터와 조회 비용을 측정하되, 현재 출처·연결 근거의 철회 검사를 생략하는 캐시는 사용하지 않는다.
