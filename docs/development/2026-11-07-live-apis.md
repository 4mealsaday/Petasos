[오디 명세](https://www.data.go.kr/data/15101971/openapi.do), [국문 관광정보 명세](https://www.data.go.kr/data/15101578/openapi.do).

## 실제 데이터와 설치의 경계

공공데이터 후보 수집기는 오디 이야기 1건과 관광정보 관광지 목록 1건→상세 1건을 최대 세 요청으로 가져온다. 상세 요청은 목록에서 실제로 받은 content ID를 사용한다. 사진·음성은 다운로드하지 않는다. 원문 응답 전체 대신 허용한 ID·제목·대본/개요·좌표·원본 갱신 시각을 정규화하고, 수집 시각·출처 페이지·내용 해시를 붙여 `.local/content/incoming/`에 저장한다.

새 후보는 `pending`이며 생성·표시·배포 허용값은 모두 false다. API 인증 성공이나 최근 수집 시각을 콘텐츠·좌표·권리 검토 완료로 취급하지 않는다. 데이터 자체는 실제 원천이지만 아직 제품에 published한 대본이나 TX-05 설치 결과가 아니다. 다음에는 대표 경로에 해당하는 자료를 골라 source/fact revision과 이용 조건을 검토한 뒤 원자적 설치로 연결한다.

현행 호출은 `Odii/storyBasedList`, `KorService2/areaBasedList2(contentTypeId=12)`, `KorService2/detailCommon2(contentId=...)`를 사용한다. 오래된 detail 조회의 `overviewYN` 플래그나 미사용 `areaCode`/`cat1~3`를 새 구현에 넣지 않는다. 오디 좌표 필드의 `mapX/mapY`와 관광정보의 `mapx/mapy`를 구분한다. 출처별 공공누리/미디어 조건은 별도 확인하며 관광정보의 사진 Type1/Type3를 텍스트 전체의 허용/금지로 확대하지 않는다. [현행 오디 API](https://www.data.go.kr/data/15101971/openapi.do), [현행 관광정보 API](https://www.data.go.kr/data/15101578/openapi.do).

## 전체 공식 API 계약 구현

공식 포털 HTML에 포함된 Swagger를 원문 값 그대로 저장하고 출처·수집 시각·SHA-256을 함께 남겼다. [공공데이터 참조 문서](../reference/public-data/README.md)에서 **오디 8개 GET, KorService2 15개 GET**의 모든 필수/선택 입력과 출력 필드를 확인한다. 제품 콘텐츠 대상 범위와 API 기술 지원 범위는 별개이며 음식점·숙박 등 새로운 제품 기능을 추가한 것은 아니다.

- `tourism_contract.py`: 공식 operation registry, 필수값·정확한 입력 이름/타입, 서술형 코드/좌표/날짜/입력 의존성 검사. `tid/tlid` 쌍, 법정동·분류 계층 조건, `searchStay2.lDongRegnCd` 필수를 적용한다. 문서상 선택인 `detailPetTour2.contentId`는 생략할 수 있다.
- `tourism_api.py`: 허용된 HTTPS 경로만 한 번 호출한다. 인증키는 내부 주입하고 한 번 URL 인코딩한다. JSON/XML의 단일/복수/빈 item, 페이지 정보, 게이트웨이 오류, HTTP 오류를 처리한다. 알려진 필드 타입 차이는 `schema_issues`로 보고하며 원래 값을 보존한다. 추가 필드도 버리지 않고 수를 보고한다. 공식 ID를 숫자로 바꾸지 않는다.
- `public_data.py`: 공통 클라이언트를 사용하는 콘텐츠 후보 변환 계층이다. 기존 1건·512KiB 제한과 pending·미디어 제외·비공개 저장을 유지한다. 일반 API 클라이언트는 미디어 URL을 필드로 보존하지만 다운로드하지 않는다.
- `scripts/public-data-api.py`: 키 없이 `list`/`describe`, 키를 읽어 `call`. 콘솔에는 개수·상태만 출력하며 원자료 저장은 `.local/content/api` 아래 `--output`을 명시할 때만 0600으로 수행한다.

공식 XML 기본값과 Petasos 기본 JSON 요청을 구분한다. 공식 Swagger에는 정식 enum/default/cardinality/nullable 선언이 없거나 불완전하므로, 원문을 수정하지 않고 서술형 제약과 관찰된 호환 처리를 분리했다. 삭제 예정 `areaCode2`/`categoryCode2`도 계약 호환을 위해 호출할 수 있으나 신규 지역·분류 연결은 `ldongCode2`/`lclsSystmCode2`를 쓴다. 일반 클라이언트의 1,000행·2MiB·10초 소켓 시간 제한은 **로컬 자원 제한**이며 공식 최대 요청량을 뜻하지 않는다. 자동 재시도·전체 페이지 수집은 없다.

### 실제 전체 호출 결과

`scripts/probe-public-data.py --check`로 실제 관광지 ID를 1건 받아 상세 조회에 사용했고, 23개 operation을 JSON/XML로 각각 한 번 호출했다. 총 47 GET이며 각 요청은 1행이다. 전체 46개 본 검사에서 **HTTP 200·업무 코드 0000**을 받았다.

| 분류 | 건수 | 확인 내용 |
| --- | ---: | --- |
| 형식·필드 타입 일치, 실제 item 수신 | 40 | JSON/XML 양쪽의 정상 데이터 |
| 문서와 타입 차이 감지 | 4 | 아래 코드 조회 JSON의 `rnum` |
| 정상 빈 목록 | 2 | 선택한 관광지의 반려동물 상세 정보 없음 |

`areaCode2`, `categoryCode2`, `lclsSystmCode2`, `ldongCode2`는 공식 `rnum: string`과 달리 JSON에서 정수를 반환한다. XML에서는 문자열이다. 이 차이를 실제 값 변조나 원문 Swagger 수정으로 숨기지 않고 `SCHEMA_DRIFT`, `item.rnum:TYPE_MISMATCH`로 기록한다. 따라서 전체 probe의 종료 코드는 1이며 인증/호출 실패가 아니라 발견한 계약 차이를 알려준다. 4개 JSON을 추가 조회해 동일 현상을 확인했다.

`detailPetTour2`는 optional `contentId`를 생략한 전체 목록 요청으로 JSON/XML 모두 실제 1건을 추가 수신했다. 이로써 **23개 API 모두 두 형식에서 비어 있지 않은 응답을 확인**했다. 코드와 필드 전체 구현 검사는 자동 시험으로 수행했으며, 모든 관광 콘텐츠 유형·모든 선택 필터 조합을 실서버에서 전수 시험했다는 뜻은 아니다.

비밀값과 원문 없는 증거: `artifacts/live-api/full-contract-probe.json`(46개 본 검사), `artifacts/live-api/contract-differences.json`(타입 차이 및 반려동물 추가 6 GET). 실제 키·전체 요청 URL·제목/대본·공급자 오류 문구는 기록하지 않았다.

## 실제 모델 연결 준비

연결 검증용 후보는 `anthropic/claude-sonnet-4.6` + `amazon-bedrock/global`이다. 이는 최종 모델 품질 평가 결과가 아니다. 공식 공개 목록에서 해당 경로의 `structured_outputs`, `response_format`, `safety_retention=false`를 확인했다. 응답 provider는 정확히 `Amazon Bedrock`, 모델은 요청 ID 또는 명시적으로 설정한 공식 canonical ID `anthropic/claude-4.6-sonnet-20260217`만 허용한다. 다른 모델·provider로 자동 fallback하지 않는다. [모델 목록](https://openrouter.ai/api/v1/models), [Sonnet endpoint 목록](https://openrouter.ai/api/v1/models/anthropic/claude-sonnet-4.6/endpoints), [ZDR 목록](https://openrouter.ai/api/v1/endpoints/zdr).

Claude/Bedrock이 지원하지 않는 일부 문자열 길이·배열 수·중복·숫자 범위 제약은 **공급자에게 보내는 스키마 복사본의 설명**으로 옮긴다. 정확히 검토한 Sonnet 모델에만 이 변환을 적용한다. 문자열/null의 서로 겹치지 않는 `oneOf`만 동등한 `anyOf`로 변환한다. 앱·서버의 v0.8 canonical schema와 응답 후 검증은 그대로라 모델이 길이/중복 등의 조건을 어기면 여전히 거부한다. [Claude 구조화 출력의 스키마 제한](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [Bedrock 구조화 출력](https://docs.aws.amazon.com/bedrock/latest/userguide/structured-output.html).

`server/probe-live-generation.py`는 실제 설정의 OpenRouter에 비개인 개발 시험 문장으로 answer·summary를 요청하고 서버의 원본 계약 검증 및 동일 요청 캐시 재사용을 확인한다. 앱→서버 구간은 메모리 ASGI transport이며 상위 OpenRouter 구간만 실제 HTTPS다. 실제 Android 통합·사용자 청취·주관적 답변 품질을 대신하지 않는다. 시험 문장·생성 본문은 artifact에 쓰지 않고 모델/provider·토큰 수·시간·상태만 기록한다. 기본값은 제품의 기존 시간 제한이며, 명시적인 60초 진단 모드는 별도 시험 인스턴스만 늘리고 제품 기한 검증 성공으로 기록하지 않는다.

최초 준비 때 `.local/server/config.json`의 provider는 비활성이었으며, dev.10에서 인증된 계정 UI의 로그·보관 조건 확인 후 아래 단일 경로를 명시적으로 활성화했다. 계정의 현재 상태는 Key API 인증 결과로 대신 검증할 수 없다. [현재 ZDR 정책](https://openrouter.ai/docs/guides/features/zdr).

### dev.10 실제 생성 결과

default 작업공간의 Input & Output Logging OFF, 무료·유료 학습 및 공개 게시 OFF, 1% 작업공간 데이터 제공 할인 OFF를 계정 UI에서 확인했다. 사용자 승인 후 Anthropic·OpenAI·Google·SpaceXAI·기타 모델의 ZDR ON, Google·기타 모델의 ZDR only 저장 완료까지 확인했다. 공개 endpoint/ZDR 목록을 같은 실행에서 다시 조회해 `amazon-bedrock/global`의 `structured_outputs`·`response_format`, 정상 status 0, `safety_retention=false`를 확인했다. 실제 생성 설정은 이 Sonnet/Bedrock 단일 경로로 유지하며 다른 모델 endpoint를 자동 선택하지 않는다.

설정은 기존 후보 Sonnet 4.6·Amazon Bedrock global, 출력 토큰 최대 2048, 명시적 응답 모델/provider 검증, fallback 금지, `data_collection=deny`, `zdr=true`를 유지한다. 검토 유효기간은 **2026-11-08 12:47:34 UTC**까지 1일이며, 만료 시 새 요청은 실패한다. `.env` 비밀값과 승인 파일은 0600으로 유지했고 config는 원자 교체했다.

| 실제 실행 | 결과 | 시간·토큰 |
| --- | --- | --- |
| answer | HTTP 200, v0.8 schema·의미·현재 근거 검사 통과 | 5,140 ms, 입력 1093·출력 103 token |
| 동일 requestId 재요청 | 동일 결과 캐시 재사용, 추가 상위 호출 0 | 메모리 캐시 |
| summary | HTTP 200, 완료 키 집합·schema 검사 통과 | 5,060 ms, 입력 1240·출력 129 token |

상위 OpenRouter POST는 총 2회이며 모두 실제 `anthropic/claude-sonnet-4.6` / `Amazon Bedrock` 응답이다. 60초 진단 모드를 사용하지 않고 **제품 14초 서버 기한** 안에서 통과했다. 고정된 비개인 개발 문장을 사용했고 입력·생성 본문은 로그/artifact에 남기지 않았다. 검토 메타데이터는 `artifacts/milestone-9/provider-review.json`, 실행 증거는 `artifacts/milestone-9/live-generation.json`이다.

이 검사는 메모리 ASGI의 실제 인증/서버 계약과 실제 상위 HTTPS 모델 경로를 잇는다. Android의 실제 사용자 발화·TTS 청취·관광 사실의 품질/환각 평가 또는 공개 배포 검수가 아니다. summary의 완료 목록도 개발 시험 입력이며 사용자가 실제 답변을 들었다는 기록을 생성하지 않는다.

### dev.10 Android HTTPS 연결과 동작 권한 보정

Mac loopback HTTPS와 adb reverse를 연결하고, `generation-provision`으로 기기 bearer token을 제품 Keystore 설정에 저장하는 검사를 통과했다. 개발 CA 신뢰는 debug APK의 localhost에만 추가했으며 제품 `HttpsGenerationTransport`의 인증서/hostname 검증과 redirect 금지는 유지한다. 공개 서버 배포나 시스템 CA 설치는 수행하지 않았다.

최초 Android `generation-live`는 약 4.9초 뒤 `INVALID_RESPONSE`로 실패했다. 후속 고정 비개인 문장 1회 재현에서는 실제 HTTPS 응답이 HTTP 200/JSON, canonical SuccessResponse 유효, 요청 상관관계·metadata 타입 정상인 동시에 `action=stop`, `targetContentId=null`이었다. 현재 제품 `RoomContentContext`와 앱 probe는 `continue`/`unsupported`만 허용하므로 이 응답은 로컬 동작 권한을 통과하지 못한다. 이 진단은 키·입력·생성 본문을 출력하거나 저장하지 않았으며 `artifacts/milestone-9/live-generation-contract-diagnostic.json`에 상태·타입·검증 결과만 기록했다.

클라이언트의 허가를 넓히는 대신 서버 모델용 answer schema를 현재 지원 동작 `continue`/`unsupported`로 제한했다. 모델용 prompt와 `petasos-v0.8-2` 버전을 함께 갱신하고, 기존 서버 응답 검증도 이 제한을 검사한다. canonical v0.8 wire enum은 그대로이며 next/music/stop/replay를 모델 제안만으로 실행하지 않는다. answer 요청에는 허용 동작 목록/대상 후보를 담는 계약이 없으므로 더 넓은 동작 연계는 별도 구현·권한 설계가 필요하다.

보정 후 서버 **167개** 자동 검사를 통과했다(`artifacts/milestone-9/server-tests.log`). 모델용 enum과 canonical enum 분리, 허가 밖 action+null 대상 거부, 지원 동작 수신을 추가 검증했다. Android JVM에는 실제 형태의 provider metadata·정수 사용량 수신과 stop+null 로컬 권한 거부 회귀를 추가했다. 최초 실패 증거는 `artifacts/milestone-9/generation-live/`, 제품 설정 저장 증거는 `artifacts/milestone-9/generation-provision/`에 보존했다.

수정한 서버를 재시작한 뒤 **2026-11-07 13:44 UTC, Pleos Connect 2.1.0/API 34, Android 사용자 10**에서 실제 Android `generation-live` 재검증을 통과했다. 전체 **10,584 ms**, 종료 코드 0, host timeout/오류 없음이다. 기본 Android HTTPS trust와 `HttpsGenerationTransport`로 비개인 고정 문장의 답변 검증, 동일 요청 재전송 결과 일치, 요약·완료 키 검증, probe 완료의 4개 이벤트를 확인했다. 결과는 `artifacts/milestone-9/generation-live-final/generation-live.json`과 `generation-live.txt`에 있다. 원래의 실패 기록은 덮어쓰지 않았다.

이 최종 검사는 **실제 Android → localhost TLS → 승인된 OpenRouter 모델 → Android 응답 검증**의 연결 증거다. 마이크 입력·TTS 출력·사용자의 실제 답변 청취·Room에 완료 청취나 요약을 저장하는 검사는 포함하지 않는다. 요약 요청의 완료 목록은 비개인 개발 시험 입력이며 실제 청취 완료로 주장하지 않는다. 생성 본문은 로그/artifact에 남기지 않았고 제품의 answer/서버 기한 15초/14초와 동작 허가를 그대로 적용했다.
