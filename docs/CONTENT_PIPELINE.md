# Petasos 콘텐츠 구조 (v1, 2026-11-10)

데모와 실제 서비스가 **같은 파이프라인**으로 이야기와 랜드마크를 만든다. 데모는 그 결과를 미리 만들어 APK에 고정한 것이고, 서비스는 같은 코드를 서버에서 필요할 때 실행한다. 앱은 콘텐츠가 어디서 왔는지(번들/서버) 몰라도 같은 방식으로 쓴다.

## 1. 흐름

```
[출처 어댑터]            [정규화 저장소]           [생성]                    [팩]                [앱]
TourAPI ─┐                                     가이드 프롬프트(버전)
국가유산 ─┼─→ Place · Fact (출처·라이선스·좌표) ─→ 이야기 / 랜드마크 소개 ─→ Content Pack ─→ 번들(데모)
Odii ────┤                                     근거 검사(evidence)                       └→ 서버 조회(서비스)
직접 작성 ┘
```

- **출처 어댑터**: 출처마다 하나. 입력은 지역 코드 또는 좌표·반경, 출력은 공통 `Place`/`Fact`. 새 출처를 붙여도 아래 단계는 바뀌지 않는다.
- **정규화 저장소**: 서버 쪽 캐시(파일 또는 SQLite). 같은 출처 ID는 다시 받지 않는다.
- **생성**: 사실(Fact)만 근거로 쓴다. 기존 서버의 evidence 검사(근거 ID·철회 확인)를 그대로 쓴다.
- **팩**: 앱이 받는 유일한 형식. 데모 번들과 서버 응답이 같은 형식이다.

## 2. 데이터 형식 (요지)

**Place**
- `placeId`(출처:원본ID), `name`, `lat`, `lng`, `regionCode`(시군구), `category`(관광지·문화시설·유산·자연·건축물 …)
- `visibility`: `small`(약 150m에서 보임) / `large`(약 1km, 탑·경기장·큰 다리·산)
- `source`, `license`, `sourceUrl`, `fetchedAt`

**Fact**
- `factId`, `placeId` 또는 `regionCode`, `text`(한 문장 사실), `source`, `license`

**Content Pack**
- `packId`, `version`, `promptVersion`, `createdAt`
- `scope`: `{ type: "route" | "region", ... }` — 경로 팩은 경로 좌표·지나는 지역 목록 포함
- `stories[]`: 기존 이야기 번들 형식(지역 연결·문단·근거 factId) + `interestScores`(관심사 12개 관련도, 1차 전에는 비워 둠)
- `scoringVersion`: 점수 계산 방식 버전
- `landmarks[]`: `placeId`, 좌표, `visibility`, `intro`(1~2문장), 근거 factId
- 앱 설치는 기존 `ContentBundleCodec`/`RoomContentInstaller`를 확장해서 쓴다(새 설치 경로를 따로 만들지 않는다).

## 3. 데모 시나리오

```
demo/scenarios/<scenarioId>/
  scenario.json    # 이름, 출발·도착, 팩 ID, 영상 모드 설정
  route.json       # 경로 좌표(네이버 길찾기 1회 결과를 고정)
  route.gpx        # 에뮬레이터 재생용
packs/<packId>.json  # 파이프라인으로 만든 팩(앱 assets로 복사)
```

- 첫 시나리오: `seoul-daejeon`(지금 데모).
- 새 데모 추가 = 출발·도착 지정 → 파이프라인 실행 → 팩 검토 → 시나리오 폴더 추가. 앱 코드는 바꾸지 않는다.
- DEMO 빌드는 들어 있는 시나리오 목록에서 고른다(설정의 DEMO 항목).

## 4. 실행 방식

| | 데모 | 서비스 |
| --- | --- | --- |
| 실행 | `server/tools/build_pack.py --scenario seoul-daejeon` (Mac에서 한 번) | 서버 엔드포인트가 같은 함수를 호출 |
| 범위 | 경로 양옆 약 2km의 장소, 지나는 지역 전부 | 앱이 요청한 지역·좌표 주변, 또는 목적지 경로 |
| 검토 | 사람이 팩을 읽고 확정 | 근거 검사 통과분만, 결과는 서버 캐시 |
| 앱 | assets 번들 설치 | `GET /v1/packs/region/{code}`, `POST /v1/packs/route`(2차) |

## 5. 이야기 프롬프트

- 프롬프트는 코드에 박지 않고 `server/prompts/` 아래 파일로 둔다: `guide_persona.md`(말투·태도), `story.md`, `landmark_intro.md`, `answer.md`. 파일마다 버전을 붙이고, 팩에 `promptVersion`을 기록한다.
- 프롬프트를 바꾸면 같은 사실로 팩을 다시 만들어 이전 버전과 나란히 비교한다: `build_pack.py --compare <이전 packId>`가 지역별로 두 버전 문장을 나란히 출력.
- 가이드 말투 방향(v1 초안, 사용자와 다듬을 것): 사람 가이드가 차 안에서 말하듯, 첫 문장은 창밖·지금 위치에서 시작, 구체적인 장면·숫자 하나, 과장·감탄사·"~라고 할 수 있습니다" 금지, 문장은 짧게, 끝에 가볍게 말을 거는 한 문장. 근거에 없는 사실은 쓰지 않는다.

## 5-1. 후보 점수와 선택 (생성 풀과 개인 선택 분리)

두 단계를 나눈다. **무엇을 만들어 둘지**(공용)와 **누구에게 무엇을 먼저 틀지**(개인)다.

1. **생성 풀(서버, 모든 사용자 공용)**
   - 지역마다 출처 어댑터로 장소·사실을 넓게 모은다.
   - `Scorer`가 후보 사실 묶음마다 점수를 매긴다: 근거 풍부함(사실 수·개요 길이), 장소 중요도(유산 등급·관광지 분류), 경로와의 거리, 이야기 소재의 다양성(이미 만든 이야기와 겹치는 정도).
   - 점수 상위부터 이야기를 생성해 지역당 N편(예: 5~10편)의 풀을 서버 캐시에 둔다. 처음 요청이 올 때(또는 목적지 경로 예측 때) 만들고, 이후 사용자는 캐시를 쓴다.
   - 사용자마다 따로 생성하지 않는다(비용·지연). 개인화는 선택 단계에서 한다.
2. **개인 선택(앱, 기기 안)**
   - 팩의 각 이야기에 `interestScores`(관심사 12개 각각과의 관련도 0~1)를 서버가 미리 계산해 넣는다.
   - 앱의 선택 점수 = 사용자 관심사와 `interestScores`의 가중합 + 지역을 지나는 남은 시간과 이야기 길이의 맞음 + 아직 안 들은 것 우선(청취 이력) + 직전 이야기와 다른 주제.
   - 관심사가 없으면 관심사 항목을 빼고 나머지로 고른다.

**관련도 계산 방법(서버, 교체 가능)**
- v0: 태그·분류 규칙 기반(지금의 관심 태그 정확 일치를 점수로 바꾼 것).
- v1: 임베딩 유사도. 관심사마다 설명 문장을 만들고, 이야기 본문·근거 사실과의 유사도를 0~1로 정규화. 임베딩 모델은 서버에서만 쓰고 앱에는 점수만 보낸다(기기에 모델·벡터를 넣지 않는다). 모델 후보: 다국어 임베딩 API 또는 서버 로컬 다국어 모델 — 한국어 품질과 비용으로 결정.
- 어느 방식이든 `Scorer`·`InterestScorer` 인터페이스 뒤에 두고, 팩에는 계산 방식 버전(`scoringVersion`)을 기록한다.

## 6. 랜드마크 안내 (앱 쪽 판단)

출처와 무관하게 팩의 `landmarks[]`만 본다.

- 방향 말하기: 안내 시점의 각도가 아니라 **지나갈 때 어느 쪽에 있는지**(진행 방향 기준 가로 위치의 부호)로 정한다. "잠시 후 오른쪽으로 ○○이 보여요". `large`이면서 아직 멀고 진행 방향 ±20° 안에 있으면 "앞쪽 멀리". 이미 지나갔으면 말하지 않는다.
- 속도 상한: 시속 250km 초과(영상 빨리감기)면 안내하지 않는다.
- 거리: 진행 방향 기준 가로 거리 `small` ≤150m, `large` ≤1km.
- 시점: 가장 가까워질 때까지 12초 이내가 되면 대기열에 넣고, 현재 문장이 끝났을 때 아직 지나가지 않았으면 안내한다.
- 끼워 넣기: 현재 문장이 끝나면 이야기를 잠깐 멈추고 소개 1~2문장 → 이야기 복귀. 사용자가 말하는 중이었거나 이미 지나쳤으면 버린다. 같은 장소는 한 여정에 한 번.
- 내비 경로 유무와 관계없이 동작. 내비 음성은 기존 오디오 포커스 처리를 따른다.
- 문장: 운전자에게 보라고 지시하지 않는다. "잠시 후 오른쪽으로 ○○이 보여요"처럼 알려 주는 말. 템플릿은 `방향 + 이름 + intro`.
- 후보 기준: 창밖에서 알아볼 수 있는 것, 가족 여행 분위기에 맞는 것. intro는 말투를 통일한다(변경 금지 라이선스 원문은 말투가 달라 랜드마크 intro로 쓰지 않는다 — 다른 출처나 직접 작성 사실로 대체).
- 설정: "창밖 안내" 켜기/끄기(기본 켜짐).

## 7. 단계

1. **1차 전**: 파이프라인 뼈대(TourAPI·국가유산 어댑터, Place/Fact, 팩 형식, build_pack.py) + `seoul-daejeon` 팩에 랜드마크 추가 + 앱 랜드마크 안내(6장). 기존 이야기 10편은 그대로 팩에 옮긴다(재생성하지 않음). 기존 랜드마크 정책 체계는 제거.
2. **1차 후**: 가이드 프롬프트 다듬기 → 데모 팩 재생성·비교·검토.
3. **1차 후**: `interestScores` v0(규칙 기반) + 앱 선택 점수로 교체 → 임베딩 v1로 교체 → 지역당 이야기 풀 동적 생성(점수 상위부터).
4. **2차 전**: 지역 팩 서버 엔드포인트 + 목적지 경로 예측으로 앞 지역 팩 미리 받기(재생·수집은 실제 GPS 확정만 인정).
