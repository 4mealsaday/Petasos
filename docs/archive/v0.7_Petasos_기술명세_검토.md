# Petasos — 기술 명세 검토

기준일: 2026-11-05 (KST). [Notion 기획서](https://app.notion.com/p/40fcf80747f2801fb55ec86bc8349426) 21절의 로컬 사본. 사용자 결정과 구현 제안·실행 전 검증 항목을 구분한다.

## 21. 기술 검토와 구현 규칙

검토일: 2026-11-05. 공식 Pleos·Android 문서와 현재 기획을 대조했다. 아래는 구현 계약과 검증 계획이며, SDK 실행·앱 구현 완료를 뜻하지 않는다. 음식점·카페는 사용자 요청 시 별도 검색 결과를 보여주는 P1 확장 기능으로 확정하며 첫 데모에는 넣지 않는다.

### 21.1. 먼저 확인해야 할 실행 조건

권한 이름은 [FusedLocation](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/declaring-permissions), [TTS](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/declaring-permissions), [STT](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/declaring-permissions), [NaviHelper](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/declaring-permissions)의 공식 문서 기준이다. 요청할 수 있는 권한과 실제 승인된 권한을 구분한다. 초기화·지원 여부·연결 해제·재연결을 SDK별 어댑터의 상태로 관리한다.

### 21.2. TTS·STT 연결과 버튼의 정확한 동작

**문단 완료:** 데모는 한 문단을 하나의 완료 가능한 TTS 요청으로 보낸다. 마지막 입력에 isFinal=true를 사용하고 onDone에서 해당 문단의 정상 완료를 확정한다. onStop·onError는 완료로 적립하지 않는다. 전체 이야기의 문단을 미리 재생 큐에 쌓아 버튼 뒤에도 다음 문단이 시작되는 구조는 피한다. [TTS 시작·중지](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/start-and-stop), [TTS 이벤트](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/event-listeners)

**복구 단위:** 확인한 TTS API에는 정확한 재생 offset·seek·합성 파일 내보내기 기능이 명시되지 않았다. 따라서 문단 완료 이력과 중단된 문단 ID를 기본 checkpoint로 사용한다. 중단 문단의 정확한 청취 범위는 unknown으로 남기고, 재개 시 문단 처음 또는 유효한 문단과 연결 문장을 선택한다. 음악은 플레이어가 제공하는 실제 positionMs로 복원한다. 음원 길이·audioRef는 얻을 수 있을 때만 채우며 TTS 재생 시간은 onStart/onDone으로 측정할 수 있다.

**정상 입력 순서:** 말하기 요청 접수 → 현재 이야기 문단 완료 → 짧은 마무리·유도 문장 완료 → STT request() → 실제 인식 준비/시작 이벤트 확인 → 입력 가능 표시 → 최종 결과 확정 → 마이크 종료 확인 → 응답 재생. request() 자체가 차량 마이크 인식을 시작하므로 문단이나 유도 문장을 재생하면서 미리 호출하지 않는다. SDK 초기화와 인식 시작을 구분한다. 음악 중 요청은 즉시 음악을 일시정지하고 같은 입력 절차에 들어간다. [STT 시작·종료](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/start-and-stop), [STT 결과 이벤트](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/result-listeners)

- onUpdated의 completed=true인 유효 결과를 turnId당 한 번만 제출한다. onEndedRecognition을 별도의 두 번째 발화로 제출하지 않는다. 종료가 먼저 온 경우 짧은 유예 동안 최종 결과를 기다리고 없으면 실패로 처리한다. 이벤트 순서와 유예 시간은 실측한다.
- 반복 버튼은 디바운스한다. 접수 대기·입력 중 다시 누르면 해당 입력을 취소한다. 취소로 새 입력을 시작하지 않는다. 답변 생성·재생 중 새 말하기는 이전 응답 작업을 무효화하고, 재생 중이면 현재 문단과 짧은 연결 문장 뒤 새 입력으로 전환한다.
- 입력 무음·취소·인식 실패에는 마이크를 자동으로 다시 열지 않는다. 이전 재생 의도가 유효할 때만 청취로 복귀한다.
- TTS 중지 확인 전 STT를 시작하지 않고, STT 종료 확인 전 답변 TTS를 시작하지 않는다. SDK 종료가 확인되지 않으면 다음 음성 작업을 보류하고 어댑터를 복구한다.
- 문단 종료 뒤 연결 문장 생성이 지연되면 고정 안내 문장으로 입력을 연다. 사용자를 무한히 기다리게 하지 않는다.
- 시작 실험값은 STT 시작 대기 3초, 첫 발화 무음 5초, 최대 입력 60초다. SDK 제한·실차 소음·사용자 경험에 따라 조정하며 지원이 확인된 값으로 표현하지 않는다.

**콜백 식별:** 확인한 TTS 콜백에는 앱 requestId가 없다. ID를 데이터 모델에 추가하는 것만으로 늦은 콜백 문제가 해결되지 않는다. 어댑터당 활성 요청 하나를 유지하고 종료 확인 뒤 다음 요청을 보낸다. 취소 세대와 리스너 수명을 관리하며 종료 확인 실패 시 어댑터 재연결을 거친다. 이전 onDone이 새 문단 완료로 처리되지 않는지 반드시 검증한다.

### 21.3. 중단이 겹쳐도 일관된 재생 상태

하나의 PlaybackCoordinator가 모든 이벤트를 직렬 처리한다. 아래 명칭은 Petasos 내부 설계이며 SDK API 이름이 아니다.

- **의도:** playIntent는 사용자가 청취를 계속 원했는지, interactionIntent는 현재 버튼 대화의 허용 여부다. 말하기 진입 전 의도를 보존하고 대화가 끝나면 복원한다. 정지 상태에서 질문했다고 배경 이야기를 자동 시작하지 않는다.
- **차단 사유:** focusTransient, focusLost, suspended, serviceUnavailable 등을 집합으로 관리한다. 한 사유가 해제되어도 나머지가 남으면 재생하지 않는다. 사용자 정지는 playIntent와 진행 중 interactionIntent를 해제하고 명시적 재개 전까지 유지한다.
- **전이 우선순위:** 사용자 정지·시스템 재생 불가 → 진행 중 사용자 입력 → 접수한 말하기 → 명시적 콘텐츠 선택 → 유효한 랜드마크 → 일반 이야기 편성. 주행 화면 제한은 별도 UI 정책이며 항상 음성 전체 정지를 뜻하지 않는다.
- **포커스:** 실제 오디오 포커스를 얻은 경우에만 출력한다. 영구 상실과 일시 상실을 구분하고, gain만으로 새 세션을 자동 시작하지 않는다. 내비의 동시 출력·duck 가능성은 플랫폼 정책을 따른다. 일반 이야기에 내비/긴급음 usage를 부여하지 않는다.
- **통화:** 포커스 이벤트만으로 통화였다고 단정하지 않는다. 직접 통화 상태를 확인할 수 없으면 일반 일시 중단으로 기록한다. 통화·포커스 복구 뒤에도 사용자 정지와 다른 차단 사유가 없어야 재개한다.
- **입력 중 중단:** 마이크를 종료하고 해당 입력은 취소한다. 통화 종료나 앱 복귀로 마이크를 자동 재개하지 않는다. 다시 말하기를 눌러야 한다.
- **앱·차량 수명주기:** 화면 종료와 서비스 종료를 구분한다. suspend/IGN off와 시스템 종료 시 출력·입력을 중단하고 checkpoint를 보존한다. 재시작 시 기록을 복구하되 사용자 또는 허용된 시스템 재개 요청 없이 음성·마이크를 시작하지 않는다.

[Audio Focus](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-developer-guide/audio-focus-development-guide/audio-focus-development)에는 내비와 미디어의 동시 출력 가능성이 있다. [Suspend 가이드](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-developer-guide/audio-focus-development-guide/suspend-mode-audio-focus)의 개념적 종료 예제를 실제 공개 이벤트 등록 API로 오인하지 않고, 설치 환경에서 사용할 수 있는 훅을 확인한다.

**비동기 결과 계약:** sessionId, requestId, turnId, cancelEpoch와 의존성을 기록한다. routeDependency는 none 또는 특정 routeVersion이다. 경로 변경은 이전 경로에 의존하는 예약·생성 결과만 폐기한다. 무관한 질문 답변·일반 이야기를 일괄 취소하지 않는다. 사용자 정지·세션 종료·새 발화는 관련 요청을 무효화한다. 응답 수신과 실제 재생 직전에 모두 유효성을 검사한다.

### 21.4. 미디어 서비스·음악·주행 화면

**서비스 구성:** Media3 MediaLibraryService와 MediaSession을 기본 후보로 사용하여 Pleos의 미디어 탐색 요구와 백그라운드 재생을 충족시킨다. 에피소드와 음악의 탐색 분류를 나누고 시스템 재생·일시정지·정지·다음 명령을 같은 Coordinator로 보낸다. FOREGROUND_SERVICE, FOREGROUND_SERVICE_MEDIA_PLAYBACK 및 mediaPlayback 서비스 유형 등은 target SDK에 맞춰 선언·검증한다. [Pleos Music/Audio 가이드](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-developer-guide/music-audio-app-developement-guide), [Media3 백그라운드 재생](https://developer.android.com/media/media3/session/background-playback)

TTS 서비스와 음악 플레이어는 서로 다른 출력 경로다. 시스템 MediaSession의 재생 상태·제어가 두 출력 모두와 일치하도록 어댑터를 둔다. 음악 플레이어 상태만 노출한 채 TTS가 계속 말하는 구현은 허용하지 않는다. TTS 요청자의 포커스와 실제 출력 서비스의 포커스 관계는 최소 예제로 확인한다.

**곡 완료:** 내부 음악은 데모에서 한 번에 한 트랙, 반복 OFF로 재생하여 정상 STATE_ENDED를 현재 곡 완료로 판정한다. isPlaying=false는 일시정지·버퍼링·오류에도 발생하므로 곡 완료가 아니다. 여러 곡 큐로 확장하면 자동 전환·사용자 건너뛰기를 별도로 구분해야 한다. [Player 이벤트](https://developer.android.com/media/media3/exoplayer/listening-to-player-events)

- 곡 종료 시 이야기가 준비되지 않았으면 다음 음악을 시작할 수 있다. 그 곡 도중 이야기가 준비돼도 새 곡이 끝날 때까지 기다린다.
- 사용자 다음/이전/음악 요청은 명시적 조작으로 처리하며 자동 곡 완료와 구분한다. 다음은 현재 항목을 건너뛰고, 이전은 데모에서 현재 이야기/곡의 시작으로 돌아간다. 건너뛰기는 청취 완료로 적립하지 않는다.
- 음악 중 질문 뒤에는 원래 곡과 위치로 복귀하는 것을 기본으로 한다. 사용자가 다른 콘텐츠를 명시적으로 선택하거나 재생 불가인 경우만 변경한다.
- 외부 음악 제어·곡 완료 감지·핸들 버튼을 말하기로 연결하는 기능은 P1 검증 항목이다. 일반 미디어 컨트롤러의 명령으로 마이크를 임의 시작할 수 없도록 허용 명령과 호출자를 제한한다.

**화면과 권한:** 첫 화면부터 현재 CarUxRestrictions를 적용하고 변경 이벤트를 구독한다. 출처·대본·지도·검색 결과·설정의 상세 화면은 해당 제한이 허용할 때만 제공한다. 동승자가 있다는 이유로 전면 디스플레이 제한을 해제하지 않는다. [주행 제한 가이드](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide)

Pleos STT 서비스 권한과 앱이 직접 AudioRecord로 녹음하는 권한은 다르다. 후자로 대체할 경우 Android 마이크 런타임 권한·microphone 서비스 유형·백그라운드 시작 제한을 별도 검증한다. 미디어 서비스가 켜져 있다는 이유만으로 녹음 가능하다고 전제하지 않는다. [Foreground service 유형](https://developer.android.com/develop/background-work/services/fgs/service-types)

### 21.5. 위치·여행·랜드마크·수집 판정

**실제 경로와 예상 경로:** 정밀 이동 기록은 수신한 위치 이벤트로 만들고, 내비 경로 정보와 분리한다. 공개 이벤트 목록만으로 전체 경로 polyline이나 일정한 GPS 수신 주기가 보장되지 않는다. 내비 경로가 없거나 도착·취소되면 현재 위치 모드로 전환하며 새로운 경로를 강제로 검색하지 않는다. [FusedLocation](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/intro), [Navi 이벤트](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/event-listeners)

**기록 범위:** 사용자가 Petasos 이동 세션을 시작하면 위치 기록을 시작한다. 재생 일시정지는 위치 기록 종료와 구분한다. 명시적 이동 세션 종료·서비스 종료·suspend에서 기록 구간을 닫고, 비정상 종료 뒤에는 interrupted 구간으로 표시한다. 앱을 열기만 하거나 종료한 뒤에도 상시 추적하는 기능은 데모 범위가 아니다. 기록 중임을 화면에 표시한다. 일시정지·백그라운드에서 위치 구독을 유지할 수 있는지와 필요한 서비스/권한은 실행 검증 항목이다. Pleos는 표준 Android 위치 권한·백그라운드 동작을 이 SDK의 보장으로 제시하지 않는다. mediaPlayback 서비스만으로 장시간 위치 기록이 허용된다고 가정하지 않으며, 지원되지 않는 상태는 누락 구간으로 표시한다.

- 동일한 제공자 이벤트의 중복 전달만 제거하고, 수신 위치는 원본 좌표·제공자 시각·수신 시각·품질 정보와 함께 저장한다. 값이 없거나 의심스러운 경우 품질 상태를 남기며 지도·수집 판정에는 사용하지 않는다. 수신되지 않은 구간을 정밀 이동 기록처럼 보간하지 않는다.
- LocationData의 timestamp·confidence 등 필드 형식과 단위를 실제 SDK로 확인한다. accuracyMeters가 제공된다고 전제하지 않고 nullable로 둔다. UTC 저장 시각과 단조 증가 경과 시간을 구분하고, 제공자 timestamp의 단위를 확인한 뒤 변환한다.
- 오래된 마지막 위치·권한 해제·터널·좌표 튐에는 새 자동 안내와 수집 판정을 보류한다. 위치 신선도 10초는 초기 실험값이며 confidence의 의미·단위와 함께 조정한다.
- 지역 카드는 시연 범위의 법정 시·군·구 코드로 통일한다. 읍·면·동과 장소는 이야기의 세부 태그로 둔다. 지역 판정의 원천·좌표계·버전을 기록하고 경계 부근에서 한 좌표만으로 통과를 확정하지 않는다. 국가 전체의 경계 데이터 확보를 완료했다고 가정하지 않는다.
- 주요 랜드마크는 선정 목록·접근 방향·거리 변화·경로 맥락으로 판정한다. 반경 안이라는 이유만으로 실제 접근 가능하거나 보인다고 말하지 않는다. 위치가 불확실하면 자동 삽입을 보류한다.
- 자동 랜드마크 후보는 동시에 최대 1개를 유지한다. 사용자 발화 중 통과한 후보는 즉시 만료시키고 뒤늦게 안내하지 않는다. 발화가 끝났거나 곡이 끝나도 이미 지난 후보는 부활시키지 않는다. 남은 후보도 재생 직전 위치로 다시 검사한다.
- 통과 지역은 검증된 위치 판정으로, 이야기 카드는 필수 문단들의 정상 재생 완료로 적립한다. 단순히 생성·예약·재생 시작한 것만으로 적립하지 않는다. 지역코드 또는 storyId에 unique 제약을 두고 재진입·앱 재시작으로 중복 적립하지 않는다. 대본 버전 변경만으로 새 카드를 지급하지 않는다.

### 21.6. 무기한 로컬 보관·요약·장애 복구

**저장 계약:** 앱 전용 저장소의 Room/SQLite를 기본 후보로 사용한다. RoutePoint는 tripId와 시간으로 조회하고, 청취 이벤트·요약·수집은 안정된 ID와 생성 시각을 가진다. checkpoint와 청취 완료·수집 반영은 트랜잭션으로 처리한다. 화면은 페이지 단위로 조회하며 전체 경로·대화를 매번 메모리나 LLM 입력으로 읽지 않는다. 스키마 변경에서 destructive migration으로 기록을 초기화하지 않는다.

- 원음 저장 필드·녹음 파일·오류 로그의 원음 첨부를 만들지 않는다. SDK 내부 처리와 외부 음성 서비스의 보관 여부는 별도로 확인한다. 배포한 음악·준비 음성 자산과 사용자 음성 기록을 구분한다.
- 자동 삭제 없이 기존 기록을 유지한다. 저장 공간이 부족하면 과거 기록을 지우지 않고 신규 저장 실패를 알린다. 기록 실패·위치 누락 구간을 표시하며, 저장에 실패한 항목을 저장 완료로 보여주지 않는다. 무기한 보관은 유한한 디스크에서 무한한 수집 성공을 보장한다는 뜻이 아니다.
- 각 문단 완료·정지·여행 상태 변경에서 checkpoint를 저장하고 위치는 짧게 묶어 트랜잭션으로 기록한다. onDestroy만 기다리지 않는다. 강제 종료 직전 아직 커밋되지 않은 구간은 손실될 수 있으며 실제 손실 창을 측정한다.
- Android 백업 경로가 활성화된 환경에서도 로컬 전용 정책이 유지되도록 앱 데이터 백업을 제외한다. allowBackup 설정과 OS 버전에 맞는 dataExtractionRules/백업 제외 규칙을 함께 검토한다. 기기 간 전송의 제조사 차이도 검증한다. 앱 삭제·OS 데이터 초기화까지 기록 보존을 보장하지 않는다. [Android Auto Backup](https://developer.android.com/identity/data/autobackup)
- 요약은 turnId 기반으로 중복 저장을 막고 사용자 경험·주장과 검증된 지역 사실을 구분한다. 서로 다른 발화의 취향이 충돌해도 특정 개인의 취향으로 자동 확정하지 않는다. 명시적 관심사 수정은 현재 설정만 바꾸고 과거 기록을 소급 삭제하지 않는다.
- 요약 저장 실패는 재생 실패와 분리한다. 응답을 들었다는 기록과 대화 기억이 저장됐다는 상태를 따로 표시하고, 관련 요약만 검색해 다음 대화에 사용한다.

**확정 정책 — 요약 전 장애 복구:** 최종 인식 텍스트를 기기에 암호화해 임시 보관하고, 요약 저장 성공 후 임시 텍스트만 정리한다. 요약 저장과 텍스트 제거는 한 DB 트랜잭션으로 처리한다. 실패·오프라인에는 임시 텍스트를 유지하고 재시도하며, turnId로 중복 저장을 막는다. 영구 요약·경로·청취·수집 기록은 계속 보관하고 원음은 저장하지 않는다. 복구 대상은 최종 텍스트가 디스크에 커밋된 이후의 요약 작업이며, 인식 중 발화·커밋 전 종료·키 소실까지 무손실을 보장하지 않는다. 상세 구현과 검수는 22.4절을 따른다.

### 21.7. 생성 서버·출처·편성 계약

**생성 요청:** schemaVersion, requestId, sessionId, turnId, cancelEpoch, routeDependency와 검증된 근거 목록·관련 대화 요약을 보낸다. story/answer/resume/summary 작업을 구분한다. 서버 API와 이 필드명은 내부 설계안이며 Pleos의 공식 API가 아니다.

**생성 결과:** 문단별 ID·대본·근거 ID, 사실/전승 구분, 후보 콘텐츠 ID와 복귀 계획을 반환한다. 없는 출처 ID·장소 ID·허용하지 않은 동작은 거부한다. 검색 본문이나 사용자 경험을 시스템 지시로 실행하지 않는다. 스트리밍 중인 불완전한 JSON을 바로 TTS에 넣지 않고 재생 단위 검증을 마친 뒤 사용한다. 구조 검증과 사실 검증은 별도다.

- 서버 키는 APK와 문서·저장소에 넣지 않는다. 서버의 사용자/기기 접근 제어·요청 제한·비용 상한이 없는 상태로 공개 배포하지 않는다. 차량 공용 프로필 ID는 서버 인증 수단이 아니다.
- 모델 ID·제공자·파라미터·프롬프트 버전을 고정하여 품질과 비용을 비교한다. 타임아웃·429·서버 오류·형식 오류를 구분하고, 유효한 요청만 제한적으로 재시도한다. 같은 requestId의 결과를 중복 재생·저장하지 않으며 재시도 비용이 0이라고 가정하지 않는다.
- 생성 대기 한도 15초, 재시도 최대 1회, 복귀 계획 대기 3초를 초기 실험값으로 둔다. 재시도도 동일한 전체 대기 한도 안에서 수행한다. 복귀 계획 실패는 유효 checkpoint 또는 대기로 처리한다. 이미 취소된 질문의 답을 나중에 재생하지 않는다.
- 네트워크 단절 시 배포한 검증 콘텐츠·내부 음악을 사용한다. 온디바이스 TTS/STT 지원이 없으면 미리 권리를 확보해 준비한 음성 자산 또는 음악만 사용한다. OpenRouter가 오프라인 음성 인식까지 대신한다고 표현하지 않는다.
- Naver 검색 결과는 검색 화면·원문 링크 경로에만 둔다. 생성 프롬프트·임베딩·요약·개인화 기억·복귀 계획에 전달하지 않는다. P1 구현 때 Maps와 검색의 이용 조건, 좌표계 변환·좌표 유효성, 호출 예산·오류 처리를 따로 확인한다.

**초기 편성값:** 선택 키워드가 없으면 일반 청중용 지역 이야기부터 시작한다. 동일 storyId와 핵심 사실의 자동 반복은 기본 제외하며, 사용자가 다시 요청하면 허용한다. 새 근거·다른 주제까지 같은 지역이라는 이유로 배제하지 않는다. 기본 편성은 한 이야기 뒤 음악 한 곡을 쉬는 구간으로 두는 실험안이며, 명시적 질문·유효한 주요 랜드마크는 기존 예외 규칙을 따른다. 음악을 계속 듣겠다는 요청은 다음 명시적 이야기 재개까지 유지한다. 말투·속도·안내 빈도·반복 기준은 설정 버전과 함께 관리한다.

### 21.9. 개발 전에 채워야 할 정보

1. 서울→대전 시나리오와 5개 묶음·10개 소재는 22.2절을 따른다. 실제 경로·좌표·지역 코드, 원천 이용권리·완성 대본과 음원 파일은 확보·검증해야 한다.
2. 사용자는 Pleos 가입·프로젝트 생성 전이다. 등록 후 프로젝트/패키지명·SDK 상태·이미지/서비스 버전과 최소 호출 결과를 확인한다. Gleo 생성 기능 답변 또는 샘플도 필요하다.
3. OpenRouter 모델 비교·서버 설정·인증 방법과 공공데이터/Maps 키의 설정 위치. 비용은 당장 선정 제약으로 두지 않으며 필요한 API는 사용자가 발급할 수 있다. 비밀 키 값은 문서에 적지 않는다.
4. 위치 품질 필드와 콜백 주기, TTS/STT 이벤트 순서, 미디어·포커스·suspend의 실제 동작. 이를 확인한 뒤 임계값을 조정한다.
5. 요약 전 텍스트의 암호화 임시 보관·성공 후 정리는 확정했다. 남은 것은 22.4절의 저장·재시도·중복 방지·장애 복구 구현과 검증이다.

기획 차원의 주요 누락과 요약 복구 정책을 보완했다. 그러나 실제 자원·SDK/API 실행·저장 복구 검증은 아직 남아 있으므로 구현 완료나 전체 기록의 무손실 보존을 선언하지 않는다.
