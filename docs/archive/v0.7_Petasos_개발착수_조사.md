# Petasos — 개발 착수 전 세 가지 과제 조사

[Notion 기획서](https://app.notion.com/p/40fcf80747f2801fb55ec86bc8349426) 22절의 로컬 사본. 조사 결과·사용자 결정·실행 전 검증을 구분한다.

## 22. 세 가지 준비 과제의 순차 조사와 결정

조사일: 2026-11-05. [개발 환경](https://app.notion.com/p/ce7cf80747f283d4a3848106d478aabe)과 공식 문서를 대조했다. 사용자는 Pleos 가입·프로젝트 생성 전이며, 필요한 API는 발급할 수 있다고 답했다. 비용은 현재 모델 선정의 우선 제약으로 두지 않는다. 지역은 자료에 따라 추천하고 우선 하나의 시나리오부터 정하되 여러 경로로 확장할 수 있다. 요약 전 텍스트의 암호화 임시 보관과 요약 성공 후 정리를 채택했다.

### 22.1. 첫 번째 — Pleos 실행 환경과 최소 검증

**조사 결론:** 기능 문서는 있지만 계정별 사용 가능 여부는 아직 확인할 수 없다. [프로젝트·SDK 신청 안내](https://document.pleos.ai/docs/pleos-only/create-my-project)는 Vehicle State·NaviHelper를 신청 없이 사용 가능, FusedLocation·TTS·STT·Vehicle Control을 준비 중으로 표시한다. 가입 뒤 My Project에 표시되는 실제 상태를 기록하고, 준비 중인 항목을 승인 완료로 가정하지 않는다.

**프로젝트 입력 초안:** 이름 Petasos, 카테고리 Music/Audio 후보. 설명은 “지금 지나가는 지역의 이야기를 함께 듣고, 원할 때 버튼으로 질문과 경험을 보태는 차량용 오디오 가이드”. 개발사명/팀명과 고유 앱 패키지명은 등록 시 실제 팀 정보로 정한다. 서버 음성에 필요한 Client ID·Client Secret은 프로젝트에서 발급받되 문서·채팅에 기재하지 않는다.

**환경 구성 순서:** Android Studio 준비 → 공식 Mac ARM64 SDK Update Site 추가 → API 34의 Pleos Connect v2.1.0 이미지와 Automotive AVD 생성 → RAM 4 GB·Cold boot → 호스트 마이크 입력 허용 → Virtual Console 연결. CRN은 안내상 Emulator 2.1.0 이후 입력이 필요 없다. [설치 문서](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator), [설정 문서](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/configure-pleos-connect-emulator)

현재 장비는 ARM64다. 일반 설치 위치 두 곳에서 Android Studio 앱을 찾지 못했고 기본 SDK 경로에는 Emulator·시스템 이미지가 없었다. java_home에는 OpenJDK 26.0.1이 표시되었다. 다른 설치 위치까지 조사한 것은 아니며, 이 Java 버전을 그대로 프로젝트에 사용한다고 확정하지 않는다. 설치한 Android Studio와 선택한 AGP·Gradle이 지원하는 JDK 조합으로 빌드를 검증한다. 공식 GPU 표는 Windows/Linux 외장 GPU 중심이므로 Mac에서 같은 조건을 충족한다고 수치만으로 판단하지 않는다.

[TTS 앱 등록](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/TextToSpeech/app-registration)과 [STT 앱 등록](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/SpeechToText/app-registration)은 ON_DEVICE만 사용하면 서버 등록이 필요 없다고 설명한다. 이는 해당 차량/이미지의 SDK 지원·권한까지 보장한다는 뜻이 아니다.

**재현 가능한 주행:** Android Emulator는 위치 점·경로 및 GPX/KML 재생을 제공한다. 이 입력이 Pleos FusedLocation과 내비에 그대로 전달되는지는 별도 확인한다. 전달되지 않으면 테스트 전용 위치 어댑터를 사용하되 시연에 모의 입력임을 표시한다. 위치 점프나 빠른 경로 재생은 실제 주행 성능 검증으로 계산하지 않는다. [Android Extended Controls](https://developer.android.com/studio/run/emulator-extended-controls)

Virtual Console은 차량 상태 시험에 사용한다. 설치 문서의 adb forward tcp:8088 tcp:8088 뒤 127.0.0.1:8088로 접속한다. Pleos 설정 문서는 Bluetooth 동글 연동을 지원하지 않는다고 명시하므로, 실제 휴대전화 통화 연동과 포커스/중단 이벤트 모의 시험은 구분한다. [Virtual Console](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/use-vehicle-emulator)

**Gleo 판단 절차:** 공개 [Gleo Interface](https://document.pleos.ai/docs/pleos-only/app-integration-guide/guide/core-concepts)는 Gleo가 앱 함수를 호출하는 구조다. 담당자/지원 채널에 ① 앱에서 먼저 생성 요청 가능 여부 ② 근거·요약 입력 ③ 구조화 텍스트 반환 ④ 취소·요청 식별 ⑤ 에뮬레이터 사용 권한을 묶어 확인한다. 해당 기능의 답변·샘플을 확보하지 못하면 OpenRouter 어댑터로 개발을 진행하고 Gleo 생성 지원을 주장하지 않는다. 실제 문의 발송은 하지 않았다.

### 22.2. 두 번째 — 대표 시나리오와 이야기 소재

**자료 확보 경로:** [오디 API](https://www.data.go.kr/data/15101971/openapi.do)에서 해설 대본·음성·사진, [국문 관광정보 API](https://www.data.go.kr/data/15101578/openapi.do)에서 장소·주소·좌표·설명을 가져오는 것을 기본으로 한다. 두 API 모두 개발단계 자동승인으로 안내되어 있으나 실제 서비스 키와 응답은 아직 확인하지 않았다. 지자체·박물관 자료는 사실 교차 확인에 사용한다. 공개 열람 가능한 글 전체를 바로 생성 DB에 복제하지 않고 개별 이용 조건을 기록하며, 허용된 데이터로 사실 카드를 구성한다. 특히 향토문화대전의 본문 재사용 조건은 추가 확인이 필요하다. 사실 확인 출처와 AI 입력·배포에 이용할 수 있는 원천을 분리한다.

**5개 묶음은 5개 지역 카드와 같지 않다.** 시연 소재 편성과 실제 행정구역 수집은 분리하며, 카드는 실제 통과한 지역 코드로만 적립한다. 고속도로에서 떨어진 박물관·공원을 ‘지금 보인다’고 설명하지 않는다. 서울→대전의 다른 경로로 바뀌면 실제 통과하지 않는 지역 이야기는 경로 의존 예약에서 제외한다.

**핵심 시연 흐름:** 지역 이야기 → 문단 뒤 버튼 질문 → 사용자 개인 경험에 반응 → 자연스럽게 이어 듣기 → 음악 한 곡 유지 → 다음 지역 이야기. 별도 짧은 장면에서 사용자 발화 중 랜드마크 통과·폐기, 같은 길의 다른 소재, 수동 정지 유지, 앱 재시작 뒤 요약 복구를 보여준다. 전체 장거리 이동을 짧은 시연에서 연속 실제 주행한 것처럼 표현하지 않는다. 서울 시내·대전 시내 경로는 이 데이터 구조를 재사용하는 확장 후보로 둔다.

**음원:** 내부 음원 후보는 Kevin MacLeod의 Carefree다. 공식 검색 결과에 3분 25초와 CC BY 4.0 표기가 있으며 [공식 라이선스 안내](https://web.incompetech.com/music/royalty-free/licenses/)는 크레딧 조건의 무료 사용을 안내한다. [곡 상세](https://www.incompetech.com/music/royalty-free/index.html?isrc=USUAN1400037)는 동적 본문이 도구에서 완전히 로드되지 않았으므로 실제 파일·곡별 라이선스·표기문을 대조한 뒤 채택한다. 다운로드·배포는 아직 하지 않았다. 곡 완료 검증은 원곡 전체 재생으로 하고, 짧은 영상의 편집은 제품의 자동 곡 중단과 구분한다.

### 22.3. 생성 모델 선정과 API 발급 순서

**모델 추천은 품질 평가의 출발점이다.** 비용보다 재미있는 한국어 대본·자연스러운 질문 응답·출처 충실도·지연을 우선한다. [Claude Sonnet 4.6](https://openrouter.ai/anthropic/claude-sonnet-4.6)을 대본·대화 비교 후보로, [Gemini 2.5 Flash](https://openrouter.ai/google/gemini-2.5-flash)를 실시간 응답 대조 후보로 둔다. 후보 명칭은 각각 anthropic/claude-sonnet-4.6, google/gemini-2.5-flash이며 실제 품질·지연의 우열은 아직 측정하지 않았다. 주 모델·대체 모델을 API 연동 전에 성급히 확정하지 않는다.

같은 근거 카드로 이야기 10건·질문 10건·개인 경험 5건·복귀 계획 5건을 각 후보에 실행한다. 대본 생성과 실시간 대화의 성능을 따로 평가하여 역할별 모델을 선택할 수 있게 한다. 근거 밖 사실, 이미 지난 지역의 잘못된 안내, 사용자 경험을 공인 사실로 바꾸는 답변은 탈락 조건으로 둔다. 음성으로 들었을 때의 흥미와 이해도는 사람 평가, JSON 계약·ID 유효성은 자동 검증, 응답 지연은 TTS 포함 실측으로 평가한다. 아직 이 비교를 실행하지 않았다.

[OpenRouter 구조화 출력](https://openrouter.ai/docs/guides/features/structured-outputs)은 모델 이름뿐 아니라 제공자 endpoint마다 지원이 다를 수 있다. response_format과 require_parameters 설정 및 앱 검증을 사용한다. 보관 정책 조건을 충족하는 제공자가 없으면 실패로 처리하며 조용히 조건을 완화하지 않는다. API 사용량은 관찰하되 현재 사용자가 정하지 않은 비용 상한을 임의 확정하거나 결제하지 않는다.

| 지금 2 | 공공데이터포털의 오디·국문 관광정보 두 API 활용신청 | 근거·장소 데이터 조회. 발급된 서비스 키의 실제 사용 가능 여부를 각 API에서 검사. 호출 키는 서버 로컬 설정 |

| 지도 연동 시 | 네이버클라우드 Maps 애플리케이션과 Android 지도·Reverse Geocoding 사용 설정 | 실제 앱 패키지·Maps 인증 조건에 맞춰 등록. 지도 SDK의 공개 식별자와 서버 시크릿은 구분 |
| P1 구현 시 | NAVER API HUB 지역 검색 | 음식점·카페 검색 화면 전용. 지금 발급할 필수 항목은 아님 |

API 키를 문서나 채팅에 복사하는 방식으로 전달하지 않는다. 필요한 시점에 프로젝트의 비추적 로컬 설정 파일 경로를 정하고 사용자가 입력한 뒤 키 값을 출력하지 않는 연결 검사를 한다. 현재 앱/서버 프로젝트가 없으므로 설정 경로·실제 연결은 아직 만들지 않았다.

### 22.4. 세 번째 — 확정한 요약 복구 정책과 구현

사용자는 **“요약 완료까지 암호화 임시 보관, 성공 후 텍스트 정리·요약은 계속 보관”**을 채택했다. ‘자동 삭제 없음’은 정밀 경로·요약·청취·수집 등 영구 기록에 유지하고, 요약에 성공한 처리용 임시 텍스트만 명시적 예외로 정리한다. 원음은 저장하지 않는다.

1. 최종 STT 결과를 turnId와 함께 앱 전용 저장소에 암호화하여 커밋한다. 인식 중간 결과는 최종 대화 기록으로 확정하지 않는다.
2. 임시 레코드는 turnId, tripId, turnVersion, ciphertext, nonce, keyVersion, createdAt, summaryStatus, attemptCount와 실제 응답 재생 이력 참조를 가진다. 요약에는 사용자 발화와 실제 들려준 응답을 구분하고, 생성만 된 미재생 답변을 들은 대화로 기록하지 않는다. Android Keystore의 키와 AES-GCM을 구현 후보로 사용한다. nonce는 암호화마다 새로 만들며 Keystore 하드웨어 보호 여부는 기기에서 확인한다. [Android Keystore](https://developer.android.com/privacy-and-security/keystore)
3. 답변 재생 종료·중단 등 해당 대화의 상태가 정리되면 요약을 시도하고 실패 시 로컬 대기 목록을 남긴다. 비정상 종료된 대화는 복구 시 확보된 발화와 실제 재생 이력만으로 요약한다. WorkManager에는 원문 대신 turnId만 넘기고 네트워크 조건·재시도 지연을 적용한다. 앱 시작 시 미완료 레코드를 재검사하여 저장 후 작업 등록 전에 종료된 경우도 복구한다. [WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent)
4. 생성 요약의 형식·원천 turnId·turnVersion을 검증하고, **요약 저장 + 임시 텍스트 제거를 한 DB 트랜잭션**으로 처리한다. 요약 저장 실패 시 텍스트를 먼저 제거하지 않는다. 중복 결과는 turnId 제약으로 한 번만 반영한다.
5. 요약 실패·네트워크 단절만으로 임시 텍스트를 시간 만료시키지 않는다. 제한된 자동 재시도 후에도 실패하면 보관 상태를 유지하고 다음 앱 실행 등에서 재시도할 수 있게 한다. 이 보관은 클라우드 동기화를 뜻하지 않으며, 요약 요청 시 서버·모델로 처리용 텍스트가 전송되는 것과 구분한다.
6. 작업 복구가 음성 재생이나 마이크 재시작을 일으키지 않게 한다. WorkManager는 OS가 허용하는 시점에 실행하며 강제 중지·차량 suspend 동안 즉시 실행을 보장하지 않는다.

**복구 범위:** 최종 인식 텍스트가 디스크에 커밋된 이후의 요약 작업을 복구한다. 아직 인식 중인 발화, 커밋 전 종료, 저장 공간 부족, 키 소실·앱 삭제까지 완전 복구를 보장하지 않는다. 백업 제외 정책은 임시 저장소와 관련 작업 DB에도 적용한다.

추가 검수는 ① 텍스트 저장 직후 종료 ② 서버 응답 후 요약 커밋 전 종료 ③ 동일 요약 두 번 도착 ④ 요약 실패·오프라인 ⑤ 텍스트 정리 트랜잭션 실패 ⑥ 재시작 후 자동 재생/녹음 없음이다. 모두 실행 전 계획이다.

### 22.5. 다음 실행 순서와 남은 확인

1. 사용자가 Pleos 가입·프로젝트를 생성하고 SDK 화면의 상태를 확인한다. 오디·국문 관광정보 API도 활용신청한다.
2. 개발 환경을 구성하고 위치·TTS·STT·미디어 최소 예제를 순서대로 실행한다. 현재 단계에서는 특정 SDK 동작 성공을 주장하지 않는다.
3. 서울→대전 시나리오의 실제 경로·장소 좌표를 확인하고, 허용된 원천으로 이야기 10개와 사실 카드·출처 표기를 완성한다.
4. OpenRouter 키 설정 뒤 동일 평가 묶음으로 모델을 비교하고, 한 문단 청취→버튼 발화→답변→복귀를 연결한다.
5. 암호화 임시 텍스트·요약 복구를 구현하고, 기존 14개 및 추가 6개 검수 시나리오를 수행한다.

계정 준비·시나리오 방향·비용 우선순위·요약 복구 정책에 대한 사용자 답변은 확보했다. 남은 것은 프로젝트 식별 정보, 실제 SDK 상태, 데이터/API 응답, 모델 평가와 주행 경로 검증이다. 이번 작업은 조사·설계 반영이며 앱 설치·API 호출·결제·담당자 문의 발송은 수행하지 않았다.
