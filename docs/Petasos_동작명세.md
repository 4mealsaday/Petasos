# Petasos — 동작 명세

버전 0.8 · 기준일 2026-11-06 · 연결: [제품](./Petasos_제품명세.md), [데이터·API](./Petasos_데이터_API_계약.md), [검수](./Petasos_검수명세.md)

## 1. 단일 상태 관리

**RUN-01.** PlaybackCoordinator 한 곳에서 이벤트를 직렬 처리한다. UI·SDK 콜백·미디어 명령·생성 응답은 모두 이 경로로 들어온다. DB와 외부 호출을 긴 단일 트랜잭션으로 묶지 않는다.

| 값 | 의미·수명 |
| --- | --- |
| tripId | 사용자가 시작한 이동 기록 단위. 여러 앱 실행·기록 구간을 포함할 수 있음 |
| sessionId | Coordinator 실행 세대. 재시작·suspend 후 새 세션, 이전 콜백의 재생 권한 소멸 |
| turnId | 접수된 말하기 한 번. 취소돼도 ID 재사용 안 함 |
| requestId | 한 논리 생성 요청. 같은 입력의 네트워크 재시도는 같은 ID, 내용 변경은 새 ID |
| playbackAttemptId | 문단/곡의 재생 시도. 다시 듣기는 새 ID |
| cancelEpoch | 세션 안에서 관련 재생 요청을 무효화하는 증가값 |
| stateRevision | Coordinator가 수용한 상태 변경마다 증가하는 순번 |
| playIntent | 배경 청취를 계속할 의도 |
| interactionIntent | 현재 버튼 대화를 허용하는 의도 |
| blockers | focusTransient/focusLost/suspended/serviceUnavailable 등 재생 차단 사유 집합 |

tripId가 같아도 sessionId가 다르면 이전 실시간 응답은 재생하지 않는다. 영구 요약 복구는 별도 작업으로 수행하며 재생 권한을 갖지 않는다.

## 2. 상태와 전이

상태는 IDLE, STORY, MUSIC, TALK_PENDING, PROMPT, LISTENING, GENERATING, ANSWERING, RESUMING, PAUSED다. TTS·음악·STT 어댑터는 READY/ACTIVE/STOPPING/UNAVAILABLE를 별도 관리한다. STOPPING이 끝나기 전에 반대 음성 작업을 시작하지 않는다.

**RUN-02.** 우선순위는 사용자 정지·시스템 출력 불가 → 진행 중 입력 → 접수된 말하기 → 명시적 콘텐츠 선택 → 유효한 랜드마크 → 일반 편성이다. UI 제한은 출력 차단과 독립적이다.

| 현재 상태·이벤트 | 조건 | 다음 상태·동작 | 저장·실패 처리 |
| --- | --- | --- | --- |
| IDLE/PAUSED + 재생 | 유효한 사용자/허용된 시스템 요청, blockers 없음 | 유효한 checkpoint 또는 콘텐츠로 RESUMING | playIntent=true. 후보 없으면 IDLE |
| STORY/ANSWERING + 말하기 | 디바운스 통과 | TALK_PENDING. 현재 문단만 마무리 | turn 생성, 기존 응답 후속 문단 무효화, 배경 의도 보존 |
| MUSIC + 말하기 | 음악 정지 확인 | PROMPT→LISTENING | 곡·위치 checkpoint. 끝까지 듣기 규칙의 명시적 예외 |
| IDLE/PAUSED + 말하기 | 입력 가능 | PROMPT→LISTENING | 배경 playIntent=false 유지 |
| GENERATING/RESUMING + 말하기 | 명시적 새 입력 | 이전 실시간 요청 취소, PROMPT | 이전 turn은 interrupted로 동결, 새 turn 생성 |
| TALK_PENDING + 현재 문단 완료 | 활성 attempt와 일치 | PROMPT | 현재 문단 완료 저장 후 마무리·유도 문장 |
| PROMPT + 출력 종료 | TTS 종료 확인, 입력 권한 있음 | STT request→LISTENING | SDK 준비/시작 이벤트 후에만 입력 가능 표시 |
| TALK_PENDING/PROMPT/LISTENING + 말하기 재입력 | 중복 버튼 시간이 아님 | 입력 취소→RESUMING/PAUSED | turn 취소. 새 입력을 자동 시작하지 않음 |
| LISTENING + 최종 결과 | turn 활성, 아직 최종 결과 없음 | 암호화 임시 저장→마이크 종료 확인→GENERATING | 저장 실패면 제출하지 않고 저장 오류 안내 |
| LISTENING + 종료가 먼저 도착 | 최종 결과 없음 | 유예 시간 동안 대기 | 유예 후 결과 없으면 failed. 중복 결과 무시 |
| LISTENING + 무음/취소/오류 | 해당 turn 활성 | 마이크 종료→RESUMING/PAUSED | 최종 텍스트 없으면 요약 생성 안 함 |
| GENERATING + 유효 응답 | 요청·버전·스키마·근거 검증 통과 | ANSWERING | 개인 대화 응답은 암호화 임시 영역. 출력 전 재검사 |
| GENERATING + 실패/대기 한도 초과 | 현재 요청 | 고정 실패 안내→RESUMING/PAUSED | 오류 코드·시도 수만 저장, 뒤늦은 응답 출력 금지 |
| ANSWERING + 정상 종료 | 활성 attempt | turn 동결→RESUMING | 실제 완료 문단만 요약 대상, 요약 작업 등록 |
| RESUMING + 계획 도착 | 후보 ID·세대·의도 유효 | STORY/MUSIC/IDLE | 실패하면 고정 checkpoint, 없으면 대기 |
| MUSIC + 정상 곡 종료 | 활성 트랙, 반복 OFF | 준비된 이야기 또는 다음 음악 | 사용자 건너뛰기는 정상 곡 종료가 아님 |
| STORY + 이야기 종료 | 유효한 재생 | MUSIC 또는 IDLE | 완료 누적은 COL-02, 다음 편성은 RUN-07 |
| 모든 상태 + 사용자 정지 | 항상 | PAUSED, 출력·입력 취소 | playIntent=false, interactionIntent=false, checkpoint |
| 모든 상태 + 포커스/서비스 상실 | 항상 | PAUSED, 입력 종료 | blocker 추가, 이미 저장한 최종 발화는 요약 복구 대상 |
| PAUSED + blocker 해제 | 다른 blocker 없음 | playIntent에 따라 RESUMING 또는 PAUSED | 입력은 자동 재개하지 않음 |
| 모든 상태 + 경로 변경 | 새 경로 판정 | 경로 의존 요청만 무효화 | routeRevision 증가. 일반 답변은 보존 |
| 모든 상태 + UI 제한 변경 | 플랫폼 이벤트 | 음성 상태 유지, 제한된 화면 닫기 | 시스템 정지 이벤트가 따로 오면 정지 전이 적용 |
| 모든 상태 + 이동 종료/suspend | 항상 | 출력·입력 종료, 세션 닫기 | 구간 닫기·checkpoint. 다음 실행 자동 재생 없음 |

표에 없는 이벤트는 상태를 바꾸지 않고 처리 결과 ignored와 이유를 남긴다. 이전 세션 콜백은 무시한다. 새로운 상태/이벤트를 추가할 때 전이표와 테스트를 함께 추가한다.

## 3. 음성·음악 규칙

**RUN-03.** 한 문단은 하나의 TTS 완료 단위다. onDone만 정상 완료로 처리한다. onStop/onError는 중단이다. 중단 문단의 세부 청취 범위는 unknown이며 완료에 합산하지 않는다. 정확한 seek나 합성 파일 내보내기를 기본 전제로 삼지 않는다.

TTS 콜백에 앱 요청 ID가 없으므로 활성 요청 하나와 리스너 수명을 관리한다. 종료 확인 실패 시 다음 작업을 막고 어댑터를 복구한다. 내부 playbackAttemptId만 추가했다고 콜백 상관관계가 보장되는 것은 아니다.

**RUN-04.** STT completed=true 결과를 turn당 한 번만 확정한다. 입력 종료와 최종 결과의 순서 역전을 허용하되, 취소·유예 만료 후 결과는 제출하지 않는다. onUpdated 중간 텍스트는 영구 기록이 아니다. 음성 SDK가 주는 원음은 파일이나 일반 로그에 저장하지 않는다.

**RUN-05.** 내부 음악은 한 번에 한 트랙, 반복 OFF다. Media3 STATE_ENDED를 곡 완료로 사용한다. 음악 중 질문 후에는 원래 곡의 위치로 복귀한다. 다음은 건너뛰기, 이전은 현재 이야기/곡의 처음부터 새 시도다. 시스템 정지는 TTS와 음악 모두에 적용한다.

곡 완료 시 이야기가 없으면 다음 곡을 시작할 수 있다. 그 곡 도중 이야기가 준비돼도 곡을 마친다. 랜드마크 자동 안내도 곡을 끊지 않는다.

**RUN-06.** 포커스를 얻은 경우에만 출력한다. gain은 새 세션 시작 명령이 아니다. 직접 통화 상태를 확인할 수 없으면 중단 이유를 통화로 단정하지 않는다. 모든 blocker가 해제돼도 수동 정지는 유지한다.

**RUN-07.** 다음 편성은 사용자 의도→현재 지역의 미청취 소재→관심사 소재→음악/대기 순서다. 같은 storyId 및 같은 안정된 factId의 자동 반복을 제외한다. 명시적 다시 듣기는 허용한다. 문장 표현만 다른 사실은 같은 factId로 묶고 원천 수정본도 기존 사실 ID에 연결한다. 배포 전 편집 검토로 사실 동일성을 확정한다.

## 4. 위치·경로·수집

**LOC-01.** 실제 수신 위치와 내비 예상 경로는 별개다. 위치 없음·오래된 위치·권한 없음·낮거나 모르는 품질을 구분한다. 값이 의심스러워도 수신 원본은 품질 상태와 함께 보관하되 자동 안내·수집·거리 합산에서 제외한다. 중복은 제공자의 확실한 event ID가 있을 때만 제거한다. 동일 좌표만으로 중복이라고 판단하지 않는다.

**LOC-02.** 사용자 이동 시작부터 기록한다. 일시정지는 구간 종료가 아니다. 서비스 종료·suspend·권한/수신 단절에는 구간을 닫거나 gap을 남긴다. 재시작 시 이전 열린 구간을 interrupted로 표시한다. endedAt을 복구 시각으로 꾸미지 않고 null로 유지하며 interruptionDetectedAt과 lastObservedAt을 구분한다. 명시적 재개 시 같은 trip 아래 새 구간·세션을 만든다.

**LOC-03.** 내비 목적지/경로 변경에만 routeRevision을 증가시킨다. GPS 한 점마다 증가시키지 않는다. 내비 경로가 없으면 routeDependency=null인 현재 위치 모드다. 과거 경로에 의존한 후보를 폐기하되 이미 확보한 일반 설명·사용자 경험은 일괄 삭제하지 않는다.

**LOC-04.** 주요 랜드마크 후보는 최대 1개다. 접근 방향·거리 변화·경로 맥락·품질이 만족될 때만 생성한다. 문단/곡 종료 뒤 재검사한다. 사용자가 말하는 동안 통과하거나 유효성을 잃으면 terminal 상태 expired로 바꾸고 복구하지 않는다. 지나간 장소를 사용자가 직접 질문하는 것은 허용한다.

**COL-01.** 지역은 데모에서 법정 시·군·구 단위를 사용한다. 데이터셋 버전·코드·좌표계를 기록한다. 확인된 연속 위치와 경계 규칙으로 통과를 확정한다. 실제 방문·고유 도로 수는 P0에서 산출하지 않는다. 경계 부근 확인 횟수·거리·시간은 시연 데이터로 검증한 RegionPolicy 설정을 사용하며 설정이 없으면 적립을 보류한다.

**COL-02.** 필수 문단을 모두 완료한 이야기만 적립한다. 같은 storyVersionId에서는 여러 이동에 걸친 완료를 누적할 수 있다. 다른 대본 버전의 문단은 합치지 않는다. 한 storyId의 카드는 한 번만 지급하며 대본 수정·규칙 버전 변경으로 재지급하지 않는다. 획득 근거에는 완성된 버전과 문단별 완료 attempt ID를 보존한다.

## 5. 저장·복구

**REC-01.** 영구 기록은 trip·구간·위치·재생 시도·대화 메타데이터·요약·수집·명시적 설정이다. 임시 대화 payload는 최종 인식 텍스트, 개인 경험을 포함할 수 있는 생성 답변·연결 문장과 재생 참조다. 준비된 일반 지역 대본과 개인 대화 payload를 별도 저장한다.

**REC-02.** 최종 인식 텍스트를 암호화해 커밋한 뒤 생성 요청을 보낸다. 개인 대화 응답도 출력 전에 암호화 임시 저장한다. 저장 불가 시 새 개인 대화 처리를 보류하고 오류를 알린다. 일반 음악/준비 콘텐츠는 가능하면 계속 제공하되 기록 실패를 표시한다.

**REC-03.** 답변 종료·취소·중단으로 turn의 입력과 재생 결과가 확정되면 turn을 동결한다. 사용자 텍스트와 정상 완료된 응답 문단만 요약 내용에 사용한다. 중단 문단은 partial_unknown 메타데이터로 남기고 들은 전체 문장으로 요약하지 않는다. 생성만 된 문단도 제외한다.

**REC-04.** 요약 작업은 동결된 turnVersion의 snapshot을 사용한다. 결과 도착 시 트랜잭션 안에서 현재 버전·동결 상태·요약 미확정 여부를 다시 비교한다. 조건이 맞을 때만 요약 삽입, turn의 saved 처리, 임시 payload 삭제를 함께 커밋한다. 이전 버전 결과는 현재 payload를 삭제할 수 없다.

**REC-05.** WorkManager는 turn별 고유 작업으로 등록하고 inputData에는 turnId만 넣는다. 실제 작업은 매번 DB의 최신 동결 버전을 읽는다. DB 저장 후 enqueue 전에 종료된 경우 앱 시작 시 pending turn을 다시 등록한다. 이미 요약된 turn은 no-op이다. WorkManager 고유 작업과 DB 조건부 반영을 함께 사용한다.

**REC-06.** 요약 실패에는 임시 텍스트를 만료시키지 않는다. 연속 자동 시도는 최대 3회, 간격은 30초→2분→10분의 시작 설정이다. 실제 실행은 OS 제약을 따른다. 소진 시 retry_wait 상태로 유지하고 다음 앱 실행에서 자동 시도 묶음을 다시 시작한다. 인증/형식 오류는 설정 수정 전 자동 재시도하지 않는다. 재시작이 출력·입력을 켜지 않는다.

**REC-07.** 최종 STT 커밋 전 종료, 저장 공간 부족, 키 소실, 앱 삭제까지 복구를 보장하지 않는다. 키 소실은 blocked로 표시하고 복호화 실패 payload를 지우지 않는다. 앱 전용 데이터·작업 DB는 백업/기기 전송에서 제외하도록 설정·검증한다.

**REC-08.** 완료된 재생 시도의 terminal 전이, checkpoint, 카드 판정을 한 트랜잭션으로 반영한다. UI는 커밋된 결과만 완료·획득으로 표시한다. 위치는 작은 batch로 커밋하고 손실 가능한 미커밋 구간을 측정한다. 스키마 변경에 destructive migration을 사용하지 않는다.

## 6. 시작 설정과 실측 항목

| 설정 | 시작값 | 시계·시작점·만료 처리 |
| --- | --- | --- |
| 버튼 디바운스 | 350 ms | 같은 실행 세대의 단조 시각, 마지막 수용 버튼부터 |
| STT 준비 대기 | 3초 | request 직후부터, 만료 시 취소·어댑터 종료 확인 |
| 첫 발화 무음 | 5초 | SDK 입력 준비 후부터, 무발화 시 종료 |
| 최대 입력 | 60초 | SDK 인식 시작부터, SDK 제한보다 크게 강제하지 않음 |
| 종료 후 최종 결과 유예 | 500 ms | 종료 이벤트부터, 만료 후 실패 |
| 대화 생성 | 총 15초, 재시도 1회 | 최초 전송부터 재시도 포함, 만료 후 늦은 응답 차단 |
| 복귀 계획 | 3초 | 복귀 요청부터, 만료 후 고정 checkpoint/대기 |
| 위치 신선도 | 10초 후보 | 측정 시계 의미가 검증된 어댑터에서만 평가 |
| 대본 | 문단 10–15초·이야기 45–90초 목표 | 실제 음성으로 측정·조정, 확정 상품 길이 아님 |
| 위치 batch | 최대 1초 또는 20개 중 먼저 | 단조 시각, 종료 이벤트에서는 즉시 flush 시도 |

타이머는 TIME-02를 따른다. 재부팅/새 세션 후 이전 타이머를 이어 계산하지 않고 상태를 재판정한다. 랜드마크 반경·통과 기준, 위치 품질 의미, 지역 경계 설정은 SDK·경로 자료로 확인해야 하는 값이며 임의로 검증 완료 표시하지 않는다.

## 7. 플랫폼 연결 조건

Media3 MediaLibraryService/MediaSession과 Pleos TTS의 시스템 상태를 일치시킨다. CarUxRestrictions를 최초 화면부터 적용한다. 플랫폼의 허용 미디어 호출자와 명령만 수용하고 외부 미디어 명령으로 마이크를 시작하지 않는다.

위치·음성·내비 SDK별 READY/미지원/권한 거부/연결 끊김을 확인한다. TTS와 STT 종료 확인, suspend 훅, 백그라운드 위치 수신, 포커스 관계는 실제 에뮬레이터 검증이 필요하다. 공개 API 범위와 조사 출처는 [조사·결정 기록](./Petasos_조사_결정기록.md)에 둔다.
